# Emacs Public API Catalog

A standalone reference catalog of the API surface GNU Emacs exposes to
extension and configuration authors. Generated by introspecting a running
**GNU Emacs 30.2** in batch mode — not by parsing C source by hand — so the
catalog reflects what is actually callable/bindable at runtime.

This is a pure Emacs reference. It intentionally does not reference any other
project.

## Files

- `emacs-api.csv` — the catalog (one row per `(name, kind)` pair).
- `extract-emacs-api.el` — the extraction script (reproducible).
- `README.md` — this file.

## How it was generated

```sh
emacs --batch --no-init-file -l extract-emacs-api.el
```

The script:

1. Force-loads a broad set of in-scope standard libraries so the catalog
   reflects what authors can actually use (best-effort `require`).
2. Builds a symbol → manual-node index by scanning the installed **Elisp
   Reference Manual** (`elisp.info`) and **Emacs User Manual** (`emacs.info`)
   index nodes.
3. Enumerates every interned symbol with `mapatoms` and classifies each on its
   function side, variable side, and face side.
4. Resolves source location via `find-func` (including C primitives, since the
   nix Emacs ships the C source tree).
5. Assigns a subsystem category, tags public-ness signals, and writes CSV.

Re-running regenerates `emacs-api.csv` deterministically for the same Emacs
build. Row counts will differ on other Emacs versions/builds.

Latest run: **19,086 rows** scanned from 39,538 symbols.

## Columns

| column | meaning |
|---|---|
| `name` | symbol name |
| `kind` | `function`, `macro`, `special-form`, `command`, `user-option`, `variable`, `face`, `hook`, `major-mode`, `minor-mode`, `keymap`. A symbol can appear under multiple kinds (one row each): e.g. its function side as `command` and its variable side as `user-option`. |
| `category` | subsystem bucket (see taxonomy) |
| `arglist` | argument list for functions/macros (`help-function-arglist`); empty for variables/faces |
| `interactive` | `t` if `commandp` (callable via `M-x` / key binding) |
| `obsolete` | `t` if marked obsolete (`byte-obsolete-info` / `byte-obsolete-variable`) |
| `public` | `;`-separated heuristic tags (see below); empty if none apply |
| `source_file` | defining file; `.elc`/`.gz` normalized to `.el`; C primitives show `…/src/foo.c` |
| `source_line` | 1-based line in the source file (best-effort; empty for some C primitives/autoloads) |
| `manual_node` | `(elisp) Node` or `(emacs) Node` if documented in a manual index; empty otherwise |
| `docstring` | full docstring text |

CSV is RFC-4180 quoted: every field is double-quoted and embedded quotes are
doubled, so docstrings containing commas, quotes, and newlines parse cleanly.

## `public` tag — how to filter

Emacs has no hard public/private boundary; everything interned is callable.
The `public` column combines signals so you can filter to a sensible "public"
subset:

- `manual` — documented in the Elisp or Emacs manual index (strongest signal of
  intended-public API).
- `interactive` — a command (user-facing).
- `internal-name` — name looks internal (`--`, `internal-` prefix, or
  `-internal`/`-1`/`-impl` suffix). Treat as private.
- `obsolete` — deprecated; avoid for new work.

Example filters:

```sh
# Manual-documented, non-internal, non-obsolete symbols
python3 -c "import csv;[print(r['name'],r['kind']) for r in csv.DictReader(open('emacs-api.csv')) if 'manual' in r['public'] and 'internal-name' not in r['public'] and 'obsolete' not in r['public']]"
```

Latest run tag counts: `manual` 4847, `interactive` 3324, `internal-name` 2831,
`obsolete` 432, no-tag 9209.

## Category taxonomy

Assigned by matching the source-file basename first, then the symbol-name
prefix, falling back to `misc`:

`buffers`, `text-editing`, `point-and-mark`, `windows`, `frames`, `keymaps`,
`commands`, `minibuffer`, `completion`, `modes`, `hooks`, `faces-display`,
`mode-line`, `options-customize`, `files`, `search-regexp`, `processes`,
`syntax`, `abbrev-macros`, `registers-bookmarks`, `help-docs`,
`lists-sequences`, `strings-chars`, `numbers-math`, `symbols-properties`,
`control-flow-eval`, `misc`.

`misc` (~30%) collects genuinely cross-cutting utilities and symbols whose
defining file could not be resolved. `category` is a navigation convenience;
`source_file` + `name` are authoritative.

## Excluded subsystems

These are intentionally dropped (by source directory, file name, or symbol
prefix): mail/Gnus, calendar/diary, ERC/IRC, games, eshell/term, **Org**, and
**version control (vc/ediff)**. `comint` is kept (foundational to processes).

## Caveats

- A snapshot of one Emacs 30.2 build; line numbers and the symbol set are
  build-specific.
- `manual_node` covers ~25% of rows — only symbols present in the manual index
  nodes; absence does not mean a symbol is private.
- Category and `public` tags are heuristics, not authoritative Emacs metadata.
