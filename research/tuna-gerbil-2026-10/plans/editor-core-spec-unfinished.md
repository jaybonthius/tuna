## 2. Joint design and ownership

One native `BufferModel` implements the existing StateModel/StateModelDefinition protocol under qualified key `tuna/buffers`, schema 1 containing exactly one buffer. It owns tree, sources, anchored navigation, annotations, file baselines and history. AppState owns one publication revision and durable generation; source-local character/property, tree, decoration, navigation and file generations invalidate only their consumers. The app never duplicates source text or navigation. Standalone domain tests use the existing one-participant app/update kernel, not a second transaction engine.

A buffer has an acyclic ordered root, initially an empty group at construction, and may legitimately have no editable source. Production defaults deliberately create one editable draft; this is startup policy, not a hidden model invariant. Group/text nodes have distinct node and source IDs. Lightweight read-only values are not gaps or separate buffers. Sources appear once in logical ownership. Move preserves identities; copy creates fresh identities and unassociated drafts; replacement gets fresh resource identities except compatible field updates. Empty/read-only contexts are navigable and never acquire hidden editable storage.

`TextView` is a revision-bound derived span/boundary index. Inline joins add nothing; line terminates with structural LF only if necessary; block separates children with structural LF only if the preceding contribution lacks LF. Preserve source newlines and intentional empty lines. Structural separators have model identities and mapping but no writable bytes. All reading, lines, movement, search, copy and selection follow this flow, independent of source/storage segmentation or CSS. Views cannot be edited or retained as snapshots; source/boundary positions and live anchors support durable navigation.

The first private gap keeps UTF-8 bytes, code-point counts and LF/long-line checkpoints. Use segmented line/checkpoint indexes with lazy suffix deltas rather than copying or shifting all following line starts for each insertion at the beginning of a large file. Gap movement/resizing and explicit distant edits may be linear; measure them. Derived view indexes cache per-source length/terminator/line summaries and subtree aggregates; splice invalidation touches changed source ranges and ancestry, not the whole tree by default. Property runs and anchor/overlay collections are indexed by affected source; do not scan all other sources per key. A simple source-local run vector is allowed initially only with measured sidecar scaling. Never claim all edits are constant time.

Public reads copy only requested characters/properties; detached snapshots explicitly pay their size. A staged candidate records semantic edit descriptors and touched metadata, not a clone of each gap, the entire tree or history. Candidate reads layer normalized staged edits over unchanged storage. Prepare replacement/inverse bytes, capacity, indexes, anchor maps, metadata/history installations and result slots before apply. Concrete native PreparedStep instances reverse even partial apply; install cannot allocate, invoke user code, escape or perform I/O. Nested failure poisons the outer update. No full render/checkpoint inside a candidate. Continuation escape/re-entry and cooperative cancellation use the existing kernel and are re-proved with the real mutable source.

Logical authored modification compares current authored content/properties/structure/durable settings to a construction/restore baseline token; exclude navigation and transient/derived output. Inverse history tokens clear it when undo returns to baseline; manual edit-back may conservatively remain modified until an explicit comparison. There is no public reset/clean setter. App checkpoint capture never changes that baseline or a visited-file baseline. File-modified separately tracks source characters/coding against its saved checkpoint; property/overlay/navigation changes cannot dirty file bytes.

## 3. Command loop, quit and follow-up

The existing owner lane remains the only live-state executor. HTTP parses/copies/validates envelopes and admits them; it does not resolve bindings or mutate model state. At dequeue, resolve a command against **current** shared context. Ordered ordinary keys do not carry mandatory publication-revision equality: a browser may type faster than HTML arrives without losing keys. Run/admission epoch still gate admission; map-dependent pointer/selection/cut and asynchronous result installation have stricter fences.

Foreground sequence: validate intent/context → resolve execution-time custom binding, native standard binding or printable fallback → stage one short common update → prepare/protection/no-op checks → apply/reverse/commit → retain committed outcome → bounded synchronous projection/publication → release expensive follow-up scheduling at a separate owner boundary. Preserve existing app command outcomes and synchronous refresh contract; do not rewrite S0–S2 to defer every render. Coalescing subscriber notifications/skipping superseded detached fat morphs remains supported. A failed renderer leaves committed text/history intact with stale/unavailable projection and an explicit retry path. Analysis and network delivery never block commit or become transaction steps.

Standard bindings: printable key self-insert; Enter newline; Tab literal tab; arrows grapheme/vertical, Ctrl-or-Meta word motion according to the tested platform map; Home/End logical line; Backspace/Delete; Shift movement extends directed selection; Escape deactivates selection/cancels pending prefix; Ctrl/Meta Z undo, explicit redo chord; copy/cut/paste gestures; search/replacement and structural/property commands available as ordinary native commands without building a minibuffer or command-discovery shell. Native operation procedures remain usable by owner-submitted programmatic commands. Reserved browser/OS shortcuts are outside delivery guarantees. Define the small binding table in one native module and test the actual platform chords; do not invent a full prefix/keymap/mode framework.

Compatibility precedence is explicit: live resolver customization → native standard binding → verified printable fallback → unbound outcome. Stock legacy Enter/hello is treated as the legacy fallback, not a custom binding that shadows newline. Keep the bridge at `tuna/input.ss`: adapt stock resolver to accept the attached native command fallback while preserving its old one-argument legacy behavior; do not detect customization by comparing procedure identities, bypass live lookup, or add native core dependency on Tuna bindings. A replaced live resolver can intentionally return a command for any key; an unbound result delegates to the native fallback. Test overriding the resolver and hello at execution time, including a queued Enter before override and explicit no-buffer instances. Final integrator verifies native context injection against actual macro-expanded resolver calling convention before accepting this narrow compatibility change.

Quit is cooperative: Escape/Ctrl-G can set an owner-checked cancellation request through admission synchronization without mutating buffer state; an already queued quit also ends transient command context at its owner turn. Short ordinary edits complete atomically. Longer foreground operations such as replace-all poll before apply; the critical apply/install extent cannot be asynchronously interrupted. Precommit cancellation/exception/nonlocal exit rolls back; after commit quit cannot undo the command. No thread termination, exception injection, rollback of file effects or indefinite cancellation registry. Command failure clears temporary context/selection extension state as appropriate, closes typing amalgamation and reports safe status; the next admitted command still executes. No public pre/post-hook registration is added.

Implement one concrete internal follow-up consumer, not a provider registry: trailing-whitespace diagnostics over the current bounded logical projection range, useful rich transient overlays. It can later be replaced by package-specific analyzers using the same owned request/result shape. Capture immutable bounded characters, fixed-shape source/boundary flow records and freshness tags only when due, **not one full snapshot per key**. Tags include run, buffer/source IDs, content/property/structure generations, requested range and analyzer/config version. This consumer never copies or traverses arbitrary property values or semantic payloads; property generation is a compact fence, not property input. Workers never read live gaps or model handles. Results submit to the same owner and install only if every relevant fence still matches. Resource deletion/replacement, config changes and new run invalidate them even if cancellation did nothing. Diagnostics advance decoration/application revision only: no authored bytes, logical/file dirty flag, durable generation or user undo.

Internal scheduling starts with at most one active job and one replaceable latest pending request descriptor for this consumer. Descriptor replacement does not copy text; owner capture occurs at a due boundary. Initial testable settings are 40 ms coalescing and 200 ms maximum pending age, measured/tuned in P5 rather than advertised service guarantees. Continuous typing starts the newest eligible bounded input at maximum age even without idle; active completion immediately offers the latest pending request. Bound captured input to 256 logical lines, 64 Ki code points, **256 KiB total captured text/identifier UTF-8 bytes and 4,096 visited flow/source/boundary records**. Count visited records including zero-character contributions, not merely emitted records, so fragmented flow cannot bypass the traversal bound. Charge incremental scalar/identifier byte lengths and each fixed-shape record before copying/allocating; never encode, clone or traverse the whole source first to check a limit. Stop at any exhausted limit, report exact captured range and clipped/incomplete leading/trailing line coverage, and do not scan outside it. A clipped edge is not a logical line ending: emit trailing-whitespace diagnostics only for whitespace followed by a confirmed real logical terminator or true logical-view end, not a capture/projection cutoff. Bound worker service by chunked cancellation checks and output count (1,024 diagnostics). Coalesce one due control notification; service it between at most 32 ordinary dequeues, preserving ordinary-key relative order. A hung analyzer cannot yield eventual completion; baseline analyzer must have measured bounded service, and test-only delayed analyzers use explicit release gates. Fresh results need not exist while edits continuously invalidate every run, but useful work must start and newest output must converge promptly once a resource stabilizes. No claim that cancellation alone ensures correctness or that continuous typing always yields current diagnostics.

## 4. Projection, input and accessibility

Target-neutral node traversal/rendering consumes the same meaningful text flow as interaction. A native recording context proves order/meaning without HTML; production selects the HTML context. Output is one coherent fat-morph surface rooted at a stable buffer DOM ID, plus small semantic status. Semantic node IDs do not depend on offsets/content. No `data-ignore-morph` canonical region, shadow DOM, per-character spans, raw HTML model values or local optimistic editor. Properties and overlays split only meaningful runs; caret/active selection are derived decorations.

Bound visible output initially to 128 logical lines plus up to 16 context lines either side and 32 Ki code points total, with a clipped long-line slice around point. Output/map has a hard initial 256 KiB budget; clip at grapheme/scalar-safe boundaries and show explicit offscreen/long-line indicators. At minimum one scalar/grapheme and the caret must remain representable; pathological single clusters get a mapped summarized representation rather than unbounded markup. The shared projection range is model-owned; wheel/PageUp/PageDown sends navigation/viewport intent rather than creating per-browser canonical scroll state. Search, copy, saving and coordinates still cover the full logical buffer. No fixed-total-file linear render per key; bounding happens before slicing/escaping/maps. Limits are validated adapter options and reviewed in performance gates, not future window objects.

Source-map schema: projection run/revision, renderer/config version, visible range, and runs `(dom-id, source-id or boundary-id, char/property/structure tags, source code-point range, DOM UTF-16 segments, display transformation kind)`. Transforms explicitly cover CRLF, hidden spans, NUL/control pictures, supplementary characters, combining sequences and clipped content. Decorations/indicators have non-source mapping and cannot turn into text by counting `textContent`. Server owns and validates map-derived interaction, including strict projection/source generations for pointer and selection. Hit-testing may use temporary native DOM ranges, never canonical browser selection. Selection visual output is server committed; drag events coalesce unsent position-dependent selection requests, not typed input. Stale maps reject/resynchronize instead of clamping.

Admission bounds initially are 4,096 pending owner intents/16 MiB owned intent payload and 1,024 pending browser intents/4 MiB payload; active work is counted separately. Validate capacity under the acknowledgement/enqueue guard and return explicit 429 capacity rejection **before** 204, never acknowledge then drop. Browser overflow or known rejection pauses acquisition and reports refused/unsent input; uncertain responses use the epoch fence below. Do not retry automatically. Test sustained admitted keys, rejection reporting and bounded queue bytes; review values at P0/P5 gates.

Keyboard envelope revision 2 is a tagged exact schema for `keydown`, `insert-text`, `select`, `projection-range`, `cut`, `resynchronize` and cooperative `quit`; retain version-1 exact legacy key schema for explicit no-buffer hosts only. Common fields are version/type/run/admission-epoch, not browser identity or persistent intent IDs. Key variant preserves existing fields plus AltGraph, and no position token; source-mapped variants carry projection/source tags and bounded offsets. Text/paste payloads are valid Unicode strings with explicit admission byte limit initially 1 MiB per request; over-limit requests reject without partial insertion, larger programmatic inserts remain supported. Validate unknown/duplicate fields, types, bounds and scalar validity. No executable browser permissions or trusted read-only bypass.

Restricted printable fallback accepts a single valid printable Unicode scalar `event.key` from a non-composing event with no command modifiers, or a tested AltGraph printable event; Shift is permitted. Exclude `Dead`, `Process`, `Unidentified`, named keys and ambiguous multi-scalar key names. Arbitrary Unicode remains supported by `insert-text`/paste/model operations. This deliberately does not solve general text acquisition, dead keys, Input Method Editor (IME) composition or mobile keyboards. Prove actual ordinary ASCII/layout/emoji payload cases rather than call synthetic keydown tests a text-acquisition guarantee. Prevent defaults only on the owned surface and owned key paths, with clipboard shortcuts left able to generate clipboard events without DOM editing or duplicate insertion.

Clipboard uses synchronous trusted copy/cut/paste event data. Maintain only a detached server-projected plain-text selection payload/token, never another canonical document. Clipboard projection is capped initially at 1 MiB UTF-8; beyond that, report unsupported synchronous clipboard size rather than silently truncate or flatten every key. Copy reflects the last published committed selection; cut additionally validates that exact current selection token and successful clipboard write. A stale cut cannot delete; report that the clipboard may contain the older committed selection. Paste extracts plain text only. P0 must prove trusted keyboard clipboard paths, exact CRLF/lone-CR/NUL round trips against model text, and no deletion on stale selection or synchronous write failure. Labeled fault injection evidences synchronous ClipboardEvent write-failure handling, not actual permission denial or universal operating-system write success: the [W3C Clipboard API §6 synchronous event API](https://www.w3.org/TR/clipboard-apis/#clipboard-event-api) does not support permission-prompt blocking. The owner explicitly selected **“Defer until final acceptance”** for native browser right-click clipboard-menu proof. This changes timing, not the requirement: native-menu interaction remains unverified until actual manual/visible-browser proof and is required before P8 final editor acceptance, but does not block P0/P1. No replacement menu, hidden textarea/input widget, asynchronous clipboard implementation, browser-mode change or execution-protocol workaround is authorized by this disposition; do not delete before clipboard write succeeds.

Uncertain POST outcomes preserve the existing no-retry contract. Pause that browser's outgoing queue and request a shared owner-ordered epoch fence: under admission mutex close ordinary admission, increment epoch and append a fence behind all admitted old work; reject late old-epoch requests. Multiple requests share the pending fence. After prior work completes/cancels, publish a new-epoch full projection with a retained completed-fence marker, then reopen admission. Every later projection in that epoch retains the marker; render failure keeps admission paused. Browsers discard unsent old-epoch events, report loss/uncertainty, and resume only on completed-fence projection. Fresh run also rejects old envelopes. No automatic replay, permanent dedupe registry, exactly-once promise or per-tab application identity.

Use semantic headings/sections/pre only where roles justify them, named focusable noneditable surface, visible focus/caret, token-backed selection/diagnostic styling, logical CSS, zoom/reflow/reduced-motion support and a small status region rather than a full-buffer live region. Screen-reader reading/selection announcements require actual assistive-technology evidence. Lack of native text entry means native screen-reader editing, composition and mobile acquisition remain limitations; ARIA textbox alone proves nothing. P0/final reports must name tested assistive technology or explicitly mark it untested; no unsupported accessibility certification blocks the restricted desktop proof silently, and any essential keyboard-only failure does block it.

## 5. Files and genuine S3

File association lives on an editable source, never the group/root or flattened logical view. Visit/save/save-as/revert use the same genuine source and user history as drafts; local alias detection prevents competing editable copies within this buffer. Visit installs at an explicit text target; no buffer switching, picker/workspace or multi-file atomicity. Initial coding is strict UTF-8 with optional BOM and exact LF/CRLF/CR/mixed endings. Replacing dirty content needs explicit native confirmation; a browser cannot assert trusted overwrite. File operations initially run as explicit owner-bound external effects outside the atomic in-memory update, with honest latency reporting, not on every key.

Prepare complete load before installation. Save streams the whole associated source, independent of restriction/viewport, to a same-directory temporary file, preserves permissions and intended symlink target, checks observed canonical identity/fingerprint and refuses external conflict. Reject multiply-linked targets rather than silently sever hard links; ordinary filesystem check/replace has an acknowledged external race, not general compare-and-swap. Only synchronized successful replacement advances the saved baseline; post-replace sync uncertainty stays explicit. Save-as establishes association only at its successful boundary; failure leaves authored content intact and reports partial disk/cleanup effects if any. Revert is one undoable replacement against the newly observed disk baseline; undo never writes disk or rewinds its observed fingerprint. Tests use fresh temporary directories only, including symlink/hard-link, permissions, failed write/flush/replace/sync and alias cases.

Real model codec is its own exclusive phase after genuine domain/file contracts, implemented through the existing state protocol, not a second persistence engine. Schema 1 records buffer/root/node/source/boundary/anchor durable IDs and allocator high-water, ordered tree roles/flow/data, editable and owned read-only characters, property runs/stickiness/protection, persistent overlays, navigation/selection/restrictions/projection/preferred column, basic-text mode/settings, and source coding/file observed fingerprint/saved-content token/baseline plus dirty tracking. Baseline token must compare correctly after restore without storing redundant entire content per key; persist saved fingerprint/content token and conservative dirtiness, never assume app recovery cleaned the file. User persistent anchors declare lifetime; temporary anchors are excluded. Derived read-only output records authoritative input/qualified installed definition/version and regenerates its mapped contribution; it does not persist HTML or a flattened view. Unserializable durable data/behavior handles fail capture explicitly; never discard them or execute data.

Codec audit classifies every actual field as durable encoded, derived rebuilt, transient excluded or history-only excluded, including allocator and unavailable definitions. Built-in basic-text definitions are installed code; unknown required behavior blocks restore and preserves original checkpoint, optional supported inactive behavior may be read-only only if explicitly encoded by the schema. Validate ownership/reference kinds, scalar boundaries, run ranges, ordered tree, overlay/selection/restriction and preferred-column before first projection/admission. Restore unsaved characters rather than reread visited files; compare disk only as an inspectable conflict/unverified status, with no visited-file writes. Produce fresh live handles/run and empty undo/redo, preserving durable identities/references. Full app capture is expected linear and bounded by existing export budgets; charge before allocating and chunk source values below token limits. Default 8 MiB token/64 MiB checkpoint limits mean large-file characterization is not automatic recovery support; use explicit scratch policy overrides when testing larger captures and report refusal under defaults.

## Appendix A. Closed public API audit and revision

This appendix is normative for the staged baseline and explicitly supersedes unresolved buffer-spec §26 items. It is a **contract**, not implemented/exported bindings. Retain the old inventory as historical proposal; do not implement or silently omit it by accident. Names listed below are exhaustive semantic operations from that inventory, with explicit disposition and complete family schemas. ### A1. Shared schemas, defaults, errors and effects

Notation: `B/N/S/A/O/V` are opaque buffer/node/source/anchor/overlay/live-view handles; `R` is source/view/detached snapshot; `P` is source position `(source-id, cp-offset)` or boundary position `(boundary-id, before|after)`; `Q` is ordered logical range `{start:P,end:P}`; counts/offsets/indices are exact nonnegative fixnums except signed movement counts; IDs are nonempty owned strings. Numeric bounds are validated at entry before allocation. App clocks are unbounded exact integers. Source and node IDs differ; live handles never substitute for detached ID references off-owner. Ranges are half-open, not screen positions. Required arguments have no default. A range must map in the current view/order. Every live operation is owner-only and phase/liveness guarded; no implicit marshalling. Snapshots/owned results are safe off-owner. Files remain explicit effects, not atomic disk updates.

Detached data is recursively owned scalar/symbol/string/proper-list data, plus declared immutable definition handles for in-memory use; durable handles require qualified installed name/version/data encoding or capture fails. Descriptions/metadata reject cycles, borrowed mutable objects, procedures without declared handling, unknown intrinsic fields and HTML/CSS strings as rendering instructions. Returned strings/lists/maps/runs can be modified by their receiver without changing any model or other result. Typed native schemas refine this at implementation; value copying is explicit, not reflection.

`NodeSpec`: tagged group `{role:'group, flow:'block, layout:#f, data:(), children:[]}` or text `{role:'text, data:(), text:string required, editable?:#f, properties:[]}`. `flow` is inline/line/block; layout is #f/stack/row. Text source kind is editable or owned-read-only; trusted derived contribution additionally declares `definition:(qualified-name,version)` and owned input data, supplied by installed native code, not browser arbitrary callbacks. Authored data/owned read-only text is durable/undoable; derived refresh is non-history, non-file-dirty, with durable generation only when its authoritative inputs change. Constructors `new-group-spec`, `new-text-spec` validate exactly these fields; no public generic node class constructor. Root creation may use either kind; omitted initial is empty group.

`Edit`: `{source-id, start,end, replacement:string|Fragment, inheritance:'none, trusted-protection?:#f}`. Plain strings start with no properties. `inheritance` exactly none/source/logical; logical requires B/view context and is used by typing. `new-buffer-edit` validates fields without granting protection privilege. Trusted protection bypass is available only to native owner code with its explicit trusted policy; serialized commands cannot supply it. Insertion permission is independent of whether replacement characters copy properties: before a nonempty insertion, check the old adjacent characters' read-only values with their declared rear/front stickiness, including inside a protected run. `inheritance:'none` does not bypass a sticky protected insertion position. Deliberately nonsticky read-only neighbors may permit insertion without changing the protected existing characters; unrelated property-run splits cannot change this decision. This follows Emacs's documented insertion permission and `verify_interval_modification` checks rather than adding an unconditional interior-region lock. Old-coordinate simultaneous batch rejects overlaps and insertions strictly within consumed ranges; equal-position inserts preserve caller order; at a shared old boundary order is ending replacement, ordered insertions, beginning replacement. A batch prepares one old→new map.

`Fragment`: `{characters:string, property-runs:[start,end,map,stickiness], segments:[source-id|boundary-id, source-range, fragment-range]}` with all ranges validated and detached. Source-map tags are informational provenance, not authority for a later insertion. Plain fragment builder `new-text-fragment` validates/copies text/runs/segments. Maps have unique symbol keys; no raw HTML. Stickiness per key defaults rear #t/front #f. Catalogue face/read-only/invisible/field/help-reference is supported now; unknown data keys round-trip but have no automatic behavior. `keymap`/`syntax` executable property interpretation is deferred, with no pretend persistence of closures.

`View`: `{buffer-id, app-revision, scope, restriction, mapped span/boundary index}`; stale on any later app revision by the conservative initial contract. `Line`: `{buffer-id,revision,index,start,end,segments,terminator:#f|source-LF|boundary-LF,semantic-owner-id}`; includes trailing/empty line, excludes LF in column length. `Match`: `{buffer-id,revision,query,scope,start,end,segments,source-generation-tags}`. Scope defaults whole logical buffer under current restriction; supported explicit scope is subtree node ID or source ID, and `widened` ignores restriction. Stale iterator/view operations fail rather than use old offsets. No DOM wrapping columns.

`Context`: `{buffer-id,focus-node-id,source-id:#f,point:#f|P,mark:#f|P,selection-active?:#f,direction:forward|backward,restriction:#f|Q|subtree-ID,projection:#f|Q,preferred-column:#f|nonnegative cp-column}`. Point has typing affinity after; mark default before. Persistent preferred column is set at first vertical move, preserved across shorter target lines, reset by horizontal move, explicit point/selection/focus/text edit; stored durably with navigation. Motion targets nearest grapheme boundary at or before goal column, clamps to target logical line end, not arbitrary UTF-16 midpoint. Word unit is Unicode letter/mark/digit/underscore runs; separators otherwise, structural LF separates words. Cross-inline segmentation does not reset grapheme/word behavior. Empty/non-text context has no point; operation needing editable target raises explicit no-edit-target, not create/clamp/redirect.

`Change`: `{buffer-id, affected-source/node IDs, old/final text ranges with character/property changes, tree/anchor/navigation/decoration/file invalidations, durable?:boolean}` detached. `UpdateResult` is existing app committed/no-op/joined schema, including joined no-final-revision semantics; no new buffer transaction result. `CopyResult`: `{fragment, plain-text, selection-token:(run,buffer,range,direction,source generations,selection generation)}`. `ReplacementReport`: `{replaced-count,skipped:[mapped match,reason],affected IDs}`; empty query rejected, protected/structural-only matches explicitly skipped. Iterators do not expose mutable internal arrays.

`BufferInfo`: ID,label,live?,app revision, local generations, authored-modified?; `NodeInfo`: ID,parent-ID/#f,kind,role,flow/layout,data,ordered child IDs,source IDs,live?; `TextInfo`: source/node IDs,kind,editable/protection,length,char/property generations,file association/#f. `AnchorInfo`: ID,position/#f,affinity,lifetime,attached?; lifetime command/persistent, default command. `OverlayInfo`: ID,target(Q|node-ID),metadata,priority,creation-order,point-affinity,expansion?,evaporate?,history?. Defaults priority 0, point before, expansion #f, evaporate #t, history #f, nonempty endpoints start-after/end-before; expansion overrides endpoints to start-before/end-after. Crossed nonempty endpoints collapse to smaller mapped position, never swap; point overlays use one anchor. `HistoryInfo`: undo?/redo?,group counts,retained-payload-bytes,budget,over-budget?; estimator charges owned UTF-8 text/node/property payload once per retained object plus documented record overhead. Initial soft budget 64 MiB, retain newest complete group even oversized, revise default only with measurements/parent gate.

`FileInfo`: association?#f/path/canonical identity/observed fingerprint,coding `{utf8,bom?:#f}`,saved content+coding token,potentially-modified?,verification/conflict status. `FileResult`: status loaded/saved/reverted/reused/refused/conflict/failed, source/node IDs,path,phase,error, replacement not-replaced/replaced,synchronization complete/uncertain/not-attempted,cleanup. Save-as installs association/baseline only on synchronized success; failed/uncertain effects retain dirty status. `VerifyResult`: clean?/dirty/unassociated/conflict plus compared generation/fingerprint; exact comparison can be linear. `DisposalResult`: disposed/refused,dirty sources,cleanup/errors; confirmation `(detached dirty summary)->boolean`, default #f refuses dirty disposal. Cleanup error after disposal reports committed lifetime end, not resurrection. `RenderedFragment`: target payload,map,resource generations,run/revision/config tags; unsupported target/kind raises explicit rendering error, never raw markup fallback.

Error vocabulary is native Gerbil errors with operation/phase/safe IDs: wrong type/options, wrong-owner, closed/detached handle, invalid bounds/scalar, stale view/map/token, invalid ownership/tree/cycle, read-only/protected, no-edit-target, conflicting batch, unsupported rendering/coding/definition. File conflict/refusal/disposal are structured expected outcomes; native causes are retained for failed I/O. No silent clamping except documented motion end-of-range and preferred-column shortening. Any precommit error rolls back; postcommit failures carry committed outcome. Query miss returns #f only where listed, never void truthiness.

Effects shorthand used below: `C` characters/source char generation; `P` property generation; `T` structure generation; `N` shared navigation generation; `A` decoration generation; `F` file/coding/baseline generation; `H` authored compound undo; `D` app durable generation iff changed exported meaning. All changed visible state yields one app revision at outer commit; no-op yields neither revision nor history. Multiple effects in one update still produce one revision/durable increment. Navigation is durable (`N,D`) but not content undo. Transient decorations use `A` only, persistent user annotations `A,H,D`. File dirtiness comes only from source characters/coding differing from saved token, never P/T/N/A alone. Equal text may differ in properties; full final equality including effects defines no-op. Reads have no effects; any mentioned returned result is detached unless explicitly an opaque handle.

### A3. Explicit export/scope revisions and total inventory closure

`buffer-create` is explicitly revised to a trusted construction-protocol operation taking ModelConstruction, not an application facade operation that silently invents an owner or a second logical buffer. `new-buffer-definition` is the native public concrete provider constructor for the existing StateModelDefinition startup protocol; options are label (`"Untitled"`), validated initial NodeSpec (empty editable draft), and basic-text settings, with all host/persistence policy remaining on AppState. `new-buffer-app` is a private ordinary native composition helper in `tuna/main.ss`: startup definitions/renderer are concrete installed code, checkpoint-path defaults #f, and explicit host options use existing app policy validation. It returns an unstarted AppState; no source/files/threads before normal exclusive app startup. This adds one concrete public definition constructor, not a generic provider/model factory or editor shell module. P2 implements definition construction; P8 owns the private composition helper without adding domain behavior.

All other A2 operations stay public behavior-facing exports **except** `text-for-each-chunk`, `text-property-boundary`, `node-children`, `node-text-flow`, `node-render`, `render-context-text`, `render-context-group`, which are trusted inter-module native read/render protocol exports, not additional application facade convenience exports. `node-text` remains public; NodeInfo also provides source IDs. Protocol methods retain their names/semantics so storage/another renderer can change behind callers. `text-for-each-chunk(R,start,end,fn) → void` visits ordered detached bounded chunks `{characters,logical range,source/boundary mapping}` synchronously; callback is read-only, cannot mutate while traversal is active, and exceptions propagate without state change. Iterator consumption never retains mutable backing arrays. This operation is not omitted; P1/P3/P4 test its protocol.

Make `call-with-buffer-context(B,overrides,fn)` and `call-with-buffer-restriction(B,restriction,fn)` private command helpers, not facade exports. They temporarily override command context, restore on error/escape, reject re-entry, do not mutate canonical shared focus/restriction merely by binding, and return an owned callback value. Mutations explicitly invoked inside still join the host and carry their normal effects. P3 tests restoration. Removing public dynamic-scope surface avoids a second navigation owner; explicit `buffer-restrict!`/`buffer-widen!` stay required.

Defer `local-ref`, `local-set!`, `local-remove!`, `context-ref` and `buffer-on-before-change!`, `buffer-off-before-change!`, `buffer-on-change!`, `buffer-off-change!` entirely. These are the **eight removed proposed public operations**, not silently implemented as a generic map/hook framework. Baseline mode/options/semantic data have typed owned schema fields; commands receive Context and use explicit procedures, model prepare owns validation and runtime follows up after commit. No callback registration/token/veto/reentrant observer ordering is promised by this baseline. Future package-owned settings or change consumers use ordinary explicit native seams with a separately audited schema, not automatic generic key/value behavior. Durable arbitrary unsupported data fails codec capture, not dropped. This is compatible with preserving Tuna's existing customization outside new buffer code.

Retain buffer-history-limit! and explicit undo boundary with concrete budget semantics; do not remove them simply because the release default is measured later. Retain narrowing and preferred column; the research recommendation to drop goal column is rejected because it would degrade the reference navigation without a need. No history-clear! or logical reset-modified! is added. File APIs are later implemented in P6, not deferred outside the delivered baseline. Real S3 is P7, not deferred until another project. All 4.2–4.7 original inventory names are accounted for by A2/A3, including private compositions and protocol-only exports. New public description builders are exactly `new-group-spec`, `new-text-spec`, `new-buffer-edit`, `new-text-fragment` (plus the concrete public `new-buffer-definition` declared above); validated source/boundary positions are detached schema values accepted/checked by operations, not raw mutable handle constructors. Any further export needs explicit parent inventory revision.

### A4. Behavioral audit acceptance, not inventory coverage alone

For every A2/A3 retained operation, tests assert arguments/defaults/results, invalid/wrong-owner/closed/stale/protected cases, detached ownership, equal/empty no-op and its listed history/local/application/durable effects. Use source-named behavior groups and a matrix connecting rows to assertions, not tests that merely count exports. Cross-family gates include: old-coordinate `XYZ` batch with both anchor affinities; immutable snapshots against later edits; same flow under alternate source segmentation; goal column down through short and back to long line; character-identical property change; read-only selection all-or-nothing; crossed/point overlays and file-clean transience; callback-free partial reversal; history no full snapshots; saved-baseline undo; strict source-mapped stale rejection without rapid-key loss; real S3 field round trip. P8 independently reviews this matrix and the usable production editor, not just mechanism fixtures.
