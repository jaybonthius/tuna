## Report or fix upstream (Gerbil / Gambit)

- [ ] **`gxc -O` hangs on an empty self-loop.** Compiling a module containing `(let lp () (lp))` with the optimizer never finishes; without `-O` it compiles. Found in stage 1 on Gerbil v0.19-dev-63 / Gambit v4.9.8; reproducible with a one-line module. Tuna works around it by giving such loops a body.
- [ ] **`thread-interrupt!` blocks its caller** until the target thread runs the interrupt, and raises `abandoned-mutex-exception` in the caller when the interrupt escapes. Check whether this is intended Gambit behavior and documented; if so, note it for Gerbil users, otherwise report it. Tuna interrupts from a helper thread.
- [ ] **`append-map` in `:std/list/list` reverses each sublist.** `(append-map (lambda (x) [x (* 10 x)]) [1 2 3])` returns `(10 1 20 2 30 3)` on Gerbil v0.19-dev-63: the final fold conses each result's elements onto the accumulator. Found in stage 4. Tuna's plain-text renderer and `buffer-texts` avoid it (a test pins `buffer-texts`' order); the kernel's dependency closures and the buffers providers' `tree-texts` (order irrelevant there) still use it.
- [ ] **`gerbil test` exits 0 when tests fail.** `run-tests` in `src/tools/gxtest.ss` (lines 44–67 in the Gerbil checkout) returns 42 when the harness fails, but the `gerbil` binary's `tool-main` (`src/gerbil/main.ss`, lines 201–212) only returns that value from the program's `main` (lines 239–254, installed with `##main-set!`), which never passes it to `exit`, so the process exits 0. Confirmed on the installed v0.19-dev-63-g1cfb032c with a one-check failing suite. Tuna's `make test` works around it by requiring `OK` as the last line of the test output (`Makefile`, `test` target); remove that once fixed upstream.
- [ ] **A killed build leaves a lock that hangs the next one.** Gerbil's compiler driver (`gerbil/compiler/driver.ss`, lines 280–293 in the checkout) retries forever while `<object>.lock` exists; a build killed during the exe link leaves `.gerbil/bin/tuna__exe_.o.lock` and an empty `tuna__exe_.o`, which later counts as up to date, so the next `gerbil build` hangs at the link step. Seen in configuration stage 2. Workaround: delete `.gerbil/bin/*.lock` and the empty `*.o`, then build again.

## Tuna

- [ ] **Jobs that post several results** (carry-over from stage 3). A job's `run` returns one result. Posting partial results (for example a highlighter coloring a large text in chunks) needs a way for `run` to post through the job's validity check without finishing; deferred until a job needs it.
- [ ] **Autosave runs on the baton.** Each changed text is written synchronously while idle. Texts are persistent, so a large text could be written from a job over a snapshot instead.
- [ ] **No `fsync` before the atomic rename** of session and autosave files: a crash of the machine (not of Tuna) shortly after a save could leave an empty file on some file systems. Gambit has no portable `fsync`.

- [ ] **Session restore order is implicit.** Slots restore in the order plugins registered them; the configuration activates autosave before the layout so buffers exist before views refer to them. Make restore order explicit (dependencies between slots) before more stateful plugins arrive.
- [ ] **Plugin-built buffers lose unsaved content on a swap** (Cordis stage 2, 2026-10-14). Swapping buffers or the text store restarts every plugin that makes buffers (`*welcome*`, the demo's `*sidebar*`); they rebuild from their code, so unsaved rich content and node ids are lost and views of them fall back to the buffer's root. Plugins that own buffers should save what they need in their own session slots.
- [ ] **Hook callbacks of equal depth run in registration order** (Cordis D5): a reload can reorder them. Callbacks that care declare a depth; revisit if order bugs appear.
- [ ] **Session-owned entries always win ties with the configuration** (Cordis stage 3): evaluated bindings take the latest declaration order, so a reload of `init.ss` cannot override an evaluated binding of equal priority. Matches "the most recent evaluation wins" until a reload; revisit with the `eval-buffer` commands.
- [ ] **Shutdown with a browser connected logs HTTP closed-socket errors** (package layout stage 2, 2026-10-14): Gerbil's HTTP server logs ERROR records when the stream handler's socket closes during SIGTERM; the session still saves. Close client streams before stopping the server.
- [ ] **Service dispatch costs about 130 ns** (Cordis stage 1, `/home/jay/Code/workbench-gerbil/scratch/tuna-cordis/dispatch-bench.ss`), ten times a direct method call; renderers and editing call it per node and character. Look at the caller check and context switch if profiles show it.
- [ ] **Text reads allocate through the provider** (stage 1): each size, substring, or line read goes through one snapshot method. Measured in stage 3 (`/home/jay/Code/workbench-gerbil/scratch/tuna-views/render-bench.ss`, a 5,000-line, 405,000-character text, 40 redraws): drawing its text node costs about 64 ms, of which the text reads alone (line start, end and characters for every line) are about 22 ms; HTML reuse now makes a redraw with nothing changed about 2 ms (64 ms before), but moving point or typing still redraws the whole text node (64 ms before and after). Drawing only what is in view, or reusing HTML per line, is what would cut the rest.
- [ ] **Closing *Help* does not bring back what its view showed** (stage 3): when `display-buffer` reused an ordinary view for *Help*, `C-h q` kills *Help* and the view shows another buffer, not the one it showed before (Emacs's `quit-restore`). Also `q` inside *Help* is not bound; its root node can now carry a keymap (mouse stage 2).
- [ ] **The demo sidebar does not return after a restart** (stage 3): its buffer is rebuilt only by `C-c d`, so the restored layout drops its view. Plugins that own buffers need a way to rebuild them on restore.
- [ ] **Views and containers have no keymaps** (mouse stage 2). Lookup walks from the focused or clicked node up to the buffer's root, then the innermost input target and the global keymap; the plan's "the view and its containers" layer is not built, so part-kind bindings (`<tab-line> <mouse-1>`) stay global.
- [ ] **Keyboard focus never reaches a rich node** (mouse stage 2): it is the selected view's text node, or its buffer's root, so buttons are pushed only by clicks and `RET` is not bound on them. Node-to-node focus movement would make keyboard access possible.
- [ ] **`posn-node` walks the clicked view's whole buffer** to find the node id (stage 1), now on every click looked up; an id index in the buffers contract would make it constant time once buffers get large.
- [ ] **A click on a button that has gone falls through** (mouse stage 2): it selects the view instead of reporting a stale click.
- [ ] **Any rebind repaints every view** (mouse stage 2): the keymap generation in the HTML-reuse key is global.
- [ ] **Revisit the macOS Option-as-Meta design** (owner, 2026-10-13: "probably a cleaner solution"). Today, when an Option key is Meta, the keys plugin reads the physical key (`code`) through a hard-coded US-layout table (`tuna/plugins/keys.ss`, `option-key`), because the browser reports the composed character (`≈`) or `Dead`. Known smells: US-only mapping, shifted punctuation from a table, `navigator.platform` for Mac detection. Rejected as not clean enough: patching with `navigator.keyboard.getLayoutMap()`. Look for a better approach before building on it.
