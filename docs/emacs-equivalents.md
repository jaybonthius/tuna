# Tuna and Emacs: equivalents and divergences

Tuna is Emacs-inspired, not an Emacs clone. This page maps Tuna's concepts to Emacs's and lists every place Tuna deliberately does something differently, with the reason. It is kept current: any new divergence must be added here and in a decision record. Status: everything below is planned unless marked built.

## Equivalents

| Tuna | Emacs | Same or different? |
|---|---|---|
| Buffer | Buffer | Same idea, but a Tuna buffer is a generic piece of UI holding a tree of nodes (a file, magit, a sidebar, the minibuffer); a one-text-node buffer behaves like an Emacs buffer. Saving to a file belongs to the text, not the buffer. |
| Text | Buffer text (shared by indirect buffers) | Same, and linked to its file. Text nodes in different buffers can show the same text or a range of it, so a search-results buffer edits the file directly (Emacs's wgrep copies and writes back). |
| Text store | The gap buffer inside Emacs's C code | Tuna's is a replaceable service; the default is a persistent rope, so old versions stay valid. Built. |
| Undo by command, undo chains | `undo`, `undo-boundary`, `pending-undo-list` | Same: one group per command, consecutive self-inserts grouped up to 20, point restored to where the command left it; undoing after another command redoes. Built. |
| View | Live window (a leaf of the window tree), with its `window-point` and `window-start` | Same thing, renamed (see divergences); two views of one buffer have independent points. Built ([ADR 13](../agents/adr/0013-views-layout-and-frames.md)). |
| Selected view (`selected-view`, `select-view`) | Selected window (`selected-window`, `select-window`) | Same. Built. |
| Layout plugin | Emacs's built-in C window tree plus `display-buffer` | Tuna's is a replaceable plugin behind a small contract (the layout contract): the views in order (`view-list`), the selected view, selecting, the next view, showing a buffer in a view (`set-view-buffer`), splitting and deleting, neighbors, `display-buffer`, a plugin's locked view (`add-locked-view`), the nearest view of a kind (`nearest-view`), the frame and frame marks, and rendering from the frame. Swapping it while Tuna runs hands the views over as a neutral description (like `window-state-get`); locked views go back to their plugins. Built (default: a tree of fit and tabbed containers with pins; a two-view toy without pins). |
| Pin (`pin-part` `C-x w p`, `unpin-part` `C-x w u`) | Side windows, which `delete-other-windows` keeps (`no-delete-other-windows`) | Different: a flag on any part's link to its container, meaning "stay drawn when the frame zooms past me"; it never moves anything, and travels with the part. Built ([ADR 13](../agents/adr/0013-views-layout-and-frames.md), "Pinning"). |
| Locked part | A side window that is strongly dedicated and has `no-delete-other-windows`, as the minibuffer window is undeletable | A part a plugin owns: pinned, and the user can neither unpin nor delete it; it closes when the plugin's buffer goes. The bar holding the minibuffer and echo area is one. Built. |
| Selected part (`select-parent-part` `C-x w a`, `select-child-part` `C-x w c`) | None (i3's "focus parent") | New: the selected view or one of its containers; pinning and moving act on it. Built. |
| `move-part-left`, `-right`, `-up`, `-down` (`C-x w <left>` and so on) | `window-swap-states`, `windmove-swap-states-left` and so on | Different: moves the selected part (a view or a container) past its neighbor, into a neighboring container, or out of its container, as i3's `move`; its size and pin move with it. Built. |
| `wrap-part-tabbed` (`C-x w t`), `wrap-part-vertical` (`C-x w 2`), `wrap-part-horizontal` (`C-x w 3`) | None; on the same keys Emacs has `window-layout-transpose` (`C-x w t`), and `split-root-window-below` and `-right` (`C-x w 2`, `C-x w 3`), which add a window beside the whole window tree | New: put the selected part (a view or a container) alone in a new tabbed or fit container, which takes its size and pin, as i3's `split` and `layout tabbed`; `C-x 2`, `C-x 3` or `C-x t 2` then add beside it inside, so tabs can nest. Not for a locked part or one holding a locked part. Built. |
| `toggle-container-kind` (`C-x w k`), `toggle-container-direction` (`C-x w d`) | `window-layout-transpose` (`C-x w t`) turns every split of the frame; Emacs's `C-x w d` is `toggle-window-dedicated` | Different: change one container (the selected part, or the selected view's container) between fit and tabbed, or between horizontal and vertical, keeping its children and its last-focused child, as i3's `layout toggle`. Built. |
| Size `content` on a link | `fit-window-to-buffer`, `window-preserve-size` | A part as big as its content, kept so by the browser (the bar's one-line views). Built. |
| `no-other-view` (a buffer setting) | `no-other-window` (a window parameter) | Same effect, set on the buffer: `other-view` and the S-arrows skip views of the idle minibuffer and the echo area. Built. |
| `show-status-line` (a buffer setting) | `mode-line-format` set to nil in a buffer | Same: views of the buffer have no status line. Built. |
| `face-remapping` (a setting) | `face-remapping-alist` | Same role: faces drawn in place of others. Built (one face for another). |
| `buffer-local-value` | `buffer-local-value` | Same. Built. |
| `other-view` (`C-x o`) | `other-window` | Same; it uses only the layout contract, so it works under any layout plugin, and cycles through the views the frame shows. Built. |
| `split-view-below` (`C-x 2`), `split-view-right` (`C-x 3`), `delete-view` (`C-x 0`) | `split-window-below`, `split-window-right`, `delete-window` | Same; the new view shows the same buffer at the same point and the selected view stays selected. Through the layout contract. Built. |
| `select-view-left`, `-right`, `-up`, `-down` (`S-<left>` and so on) | `windmove-left` and so on | Same keys; moving into a container lands on the view last focused there (focus memory) rather than the geometrically nearest one, as in i3. Built. |
| `tab-new` (`C-x t 2`), `tab-next` (`C-x t o`), `tab-previous` (`C-x t O`), `tab-close` (`C-x t 0`) | `tab-bar-mode`'s commands of the same names | Same keys, different thing: a Tuna tab is a child of a tabbed container anywhere in the layout, not a saved window configuration of the whole frame (see divergences). Built. |
| `frame-to-node-at-point` (`C-x n s`), `frame-to-top` (`C-x n w`) | `org-narrow-to-subtree`, `widen` | Moving the frame onto the node holding point, and back to the whole layout; the buffer is untouched. Built. |
| `frame-zoom-in` (`C-x n i`), `frame-zoom-out` (`C-x n o`) | None (tmux's zoom, i3's fullscreen are the nearest) | New: move the frame one level down toward the selected view, or one level up (from a node to its parent node, then the view, then its containers). Built. |
| Container (fit, tabbed, scroll; each horizontal or vertical) | Internal "combination" window (horizontal or vertical split only) | Tuna adds tabs (a vertical tabbed container has side tabs), scrolling strips, and plugin-defined kinds; each container remembers its last-focused child. Built: fit and tabbed (`context-define-container-kind!` adds kinds); scroll later. |
| `display-buffer` side hints | Side windows (`display-buffer-in-side-window`), as used by treemacs and speedbar | Same role (`(display-buffer b side: 'left size: 1/5)`); the side is of what the frame shows, and a layout plugin without sides places the view its own way. A view dedicated to one buffer closes with it. Built. |
| `display-buffer` and display rules | `display-buffer`, `display-buffer-alist` | Same role, part of the layout contract. `display-buffer` is built (it reuses a view showing the buffer, else another ordinary view, else splits); display rules are not. |
| Window configuration | `window-configuration`, `window-state` | Same role. |
| Frame | Frame (a top-level window holding the whole window tree), plus narrowing | Different: a movable pointer to any part of the tree (see divergences). Initially every browser tab shows the same frame. Built (one frame). |
| Frame mark (`set-frame-mark` `C-x r w`, `jump-to-frame-mark` `C-x r j`, `list-frame-marks` `C-x r l`) | A window configuration saved to a register (`C-x r w`, `C-x r j`) | Different: jumping to a frame mark only moves the frame, so later changes to the layout are kept; a register restores a copy. A mark whose part is gone says so and is dropped. Never called just "mark", which keeps its Emacs meaning. Built. |
| Screen | What redisplay draws | Tuna sends each screen to the browser as HTML. |
| Client (a browser tab) | A terminal connected with `emacsclient` | Similar. |
| Text node | The buffer's text with its properties | Same. |
| Rich node | Nothing; Emacs fakes structure with text, properties and overlays (Magit sections, Dired lines, widgets) | New in Tuna. |
| Point, mark, region | Point, mark, region | Same. Positions count from 1. |
| Selections | Point and mark, plus packages such as multiple-cursors | A view can hold several selections, one primary. |
| Styled text | Propertized string | Same. |
| Text property, overlay | Text property, overlay | Same; Tuna overlays can be limited to one view. |
| Highlight layer (`set-highlights!`) | Overlays or `font-lock-face` properties set by a highlighter | A text holds named layers of ranges with faces; changing one bumps the decoration revision, not the content revision, and ranges move with edits. Built (minimal). |
| Marker | Marker | Same. |
| Character and content revisions | `buffer-chars-modified-tick`, `buffer-modified-tick` | Same, plus a separate revision for decorations. |
| Command (`defcommand`) | `defun` with `(interactive …)` | Same; Tuna commands will declare how each argument is obtained. Commands have their own contract and plugin: records with documentation, provenance and a visibility predicate, plus listing and named invocation. Package code imports the commands contract directly, or uses the package-author prelude. Built (modes and argument declarations are reserved, not interpreted). |
| Input session | Per-terminal command-loop state (`last-command`, prefix argument, keyboard macro) | Same idea, named. |
| Keymap stack | `current-active-maps` precedence | Same order, made explicit; adds keymaps on nodes. Keymaps belong to the keys contract and are kept by the keys plugin. Built: the focused node's keymap and those above it to the buffer's root, the innermost input target's, then the global keymap; transient, overriding, emulation and minor-mode maps are not built. |
| Node keymap (`node-keymap`, `set-node-keymap!`, `new-node … keymap:`) | The `keymap` text or overlay property | Same role, on a node instead of a range of characters: keys typed with focus in the node or below it, and clicks on it or below it, look there first. Its bindings are owner-tagged entries, gone when their plugin is turned off. Built (for clicks: [ADR 8](../agents/adr/0008-input-keymaps-and-command-composition.md), Clicks; mouse plan stage 2). |
| The keymap of a buffer's root node | The buffer's local map (`use-local-map`, `current-local-map`) | Same role; there is no separate buffer keymap. The minibuffer's prompts bind `RET` and `C-g` there. Built. |
| Button (`new-button`, `push-button`, `button-keymap`; the buttons plugin) | `button.el` (`make-text-button`, `push-button`, `button-map`, the `action` property) | Same model: a `button` node with a label and an action called with the button; every button carries `button-keymap`, where the buttons plugin binds `<mouse-1>` to `push-button`, which finds the button through `event-start` and `posn-node`. Drawn as a real `<button>` out of the browser's tab order. Unlike Emacs, `RET` does not push it: keyboard focus never rests on a button yet (see divergences). Built. |
| `buffer-list-update-hook` | `buffer-list-update-hook` | Same: runs after a buffer is added, killed or renamed. Built. |
| `keymap-set` | `keymap-set` | Same syntax (`"C-x C-f"`). Part of the keys contract. Built. |
| `mac-option-modifier` (keys plugin setting) | `ns-alternate-modifier` | Same role for left Option on macOS: `meta` (default) uses the physical US key, honoring Shift; `none` ignores Alt and uses the browser character. Resolved for each key item. Other platforms keep Alt as Meta and AltGraph as text input. Built (only `meta` and `none`). |
| `mac-right-option-modifier` (keys plugin setting) | `ns-right-alternate-modifier` | Same role for right Option: `none` by default, or `meta`. If both Options are held, either configured Meta wins; if no side was observed, the left setting applies. Physical codes follow US positions even on non-US layouts; named and unmapped keys keep their browser names. Built. |
| The `<printing-char>` binding | Printing characters bound to `self-insert-command` in `global-map` | Same effect through one pseudo-key. Built. |
| `this-command`, `last-command`, `last-command-event` | Same names | Commands owns activation identity: `this-command` and the preceding command are thread-scoped, so prompt keystrokes cannot clobber the waiting command. Named calls update the caller's preceding-command value and the completed identity; a wrapper's final identity is its last named call. The event is captured per key/click activation. Built ([ADR 8](../agents/adr/0008-input-keymaps-and-command-composition.md)). |
| `call-command` | `command-execute` with recording | Runs the named command in the current task, with activation identity and the same command-loop hooks as keys and clicks, whether or not an input provider is active. Built ([ADR 14](../agents/adr/0014-completion.md)). |
| `where-is` | `where-is-internal` | Effective bindings in the maps active from an explicit node focus, or the current focus by default; hides exact and prefix shadows, removes duplicate sequences, then orders by key count, string length and spelling. Built. |
| `pre-command-hook`, `post-command-hook` | Same names | Zero-argument hooks in the commands contract, run by the commands plugin around keys, clicks and named calls; callbacks use `this-command`. Post runs before the redraw after completion, also on errors and quit from the body. A failing callback is removed with a notice. Built ([ADR 8](../agents/adr/0008-input-keymaps-and-command-composition.md), [ADR 14](../agents/adr/0014-completion.md)). |
| Click (`mouse-1`, `C-mouse-1`, `double-mouse-1`, `triple-mouse-1`; left, middle, right are 1, 2, 3) | Mouse click events of the same names | Same names and modifier order; a click happens on release; an unbound double or triple click falls back to the single one, and the browser delivers the single click first, as Emacs does. Keys and clicks travel in one ordered queue. Built (clicks only: no `down-mouse-`, `drag-mouse-` or wheel events yet). |
| Part kind as a prefix key (`"<tab-line> <mouse-1>"`, `"<view> <mouse-1>"`, `"<status-line> <mouse-1>"`) | Fake prefix keys for clicks outside text (`[mode-line mouse-1]`, `[tab-line mouse-1]`) | Same idea and, where Emacs has one, the same area name (`tab-line` for a tabbed container's strip, not `tab`, which is the Tab key's event); the others are named after Tuna's parts; looked up in the keymaps of the node clicked and the nodes above it, the innermost input target's, then the global one. Unlike Emacs, an unbound `"<tab-line> <mouse-1>"` is then looked up without the prefix (`"<mouse-1>"`) (see divergences). Built. |
| `posn`, `event-start`, `posn-area`, `posn-part`, `posn-view`, `posn-node` | `posn`, `event-start`, `posn-area`, `posn-window`, `posn-point` | Different shape: a posn names the part clicked by its stable id (a view or status line by the view's id, a tab of a tab line by the id of the part it shows) and the node under the pointer, plus the screen it was clicked on; no pixel, column or character positions (see divergences). `posn-view` and `posn-node` return #f once the view or node is gone. Built. |
| `mouse-select-view` (`<view> <mouse-1>`, `<status-line> <mouse-1>`) | `mouse-select-window` (`[mode-line mouse-1]`, and clicks in text through `mouse-set-point`) | Same: a click selects nothing by itself; this binding selects the view. Views of buffers with `no-other-view` (the bar's) refuse quietly, where Emacs refuses an inactive minibuffer window with an error. Built. |
| `tab-select` (`<tab-line> <mouse-1>`) | `tab-line-select-tab`, `tab-bar-select-tab` | Same role, for Tuna's tabs (a tab shows a part; clicking it selects that part's last-focused view). Built. |
| `data-clickable` with hover, pressed and pointer styles | `mouse-face` and `help-echo` on clickable text | Same purpose; the renderer marks a tab or status line while a click on its kind has a global binding, and a node while its own keymap binds a plain click (a button), and the browser styles it with CSS alone. A rebind changes the keymap generation, which draws the nodes again. Built. |
| Input item and the input service | Input events and `read-key-sequence` | The kernel queues each item without looking inside it; the plugin filling the input service (the keys plugin) decides whether it means "quit" and which command it runs, much as Emacs looks events up in keymaps. Built. |
| `input-pending?`, `discard-input` | `input-pending-p`, `discard-input` | Same; part of the kernel. Built. |
| Echo area | Echo area | A plugin whose messages show in a buffer (` *Echo Area*`) in a locked view of the bar at the bottom; a message goes to the echo area view nearest the selected view (see divergences). Built. |
| Hook (`new-hook`, `context-add-hook!`, `run-hook`) | Hook | Callbacks are named and ordered by depth, then by their plugins' order in `init.ss`, so a reload cannot reorder them (Emacs: newest first at equal depth). A failing one is removed with a notice, as Emacs does only for `pre-command-hook` and `post-command-hook`; ordinary Emacs hooks stop at the error and keep the function. Adding a callback name again for the same plugin replaces it (as `add-hook` skips a function already present), and a callback given as a named function calls its current definition, so redefining it takes effect at once. The one hook mechanism is part of the kernel; each hook keeps its own callbacks. Built. |
| `kill-buffer-hook` | `kill-buffer-hook`, `replace-buffer-in-windows` | Same hook; layouts use it to show another buffer in the views that showed the killed one (`replace-buffer-in-views`), which Emacs does inside `kill-buffer`, and to close views dedicated to it. Built. |
| `after-change-hook` | `after-change-functions` | Same role; callbacks receive the text and its change record. Built. |
| `plugin-activated-hook`, `plugin-deactivated-hook`, `service-changed-hook`, `task-started-hook`, `task-finished-hook` | `after-load-functions`, for activation only | The engine announces its own events. Emacs has no general hook for unloading, services, or tasks; `pre-command-hook` and `post-command-hook` are per command and belong to the commands contract and plugin ([ADR 8](../agents/adr/0008-input-keymaps-and-command-composition.md)). Built. |
| Open package `def` / `def*`, and `redefine` | `defun`, re-evaluation with `C-M-x` | Built in Tuna-prelude modules only. Compiled and saved callers reach the latest implementation. Exports control imports, not module-context access to private functions. `redefine` is built; the `C-M-x` command comes later. |
| `def/closed` | `defsubst` / `define-inline` as an opt-out from live changes | Same purpose for measured hot spots, not identical compilation: `def/closed` keeps ordinary Gerbil optimization rather than explicitly requesting inlining. |
| `advise!`, `unadvise!`, `advice-for`, `M-x describe-advice` | `advice-add`, `advice-remove`, `advice-mapc`, advice in `describe-function` | Ten kinds, owned and removed with their plugin. Targets: open functions (private ones by module), and commands through `(command-target 'name)`. Redefinition keeps advice; final removal reveals the latest base. Built. |
| Setting (`defsetting`) | `defcustom` / variable | Same idea, with a typed schema. Built with a default and documentation; schemas come later. |
| `with-settings` | `let` on a special variable | Same effect, but per running command (see divergences). Built. |
| Buffer-, mode-, project-, connection-local values | Buffer-local, directory-local, connection-local variables | Same idea, one extensible chain. The buffer scope is built. |
| Plugin | Package, feature, minor mode | A plugin can be turned off and undone completely. |
| Receipt | `unload-feature` (best-effort) | Tuna's is exact. |
| Manifest and stub commands | Autoloads (`;;;###autoload`, `loaddefs`) | Same purpose. |
| Service | Nothing direct; closest are generic functions and backend lists (`xref`, `project`) | New in Tuna. One plugin fills each service; a plugin declares what it provides (`provides:`), needs (`requires:`) and uses when present (`optional:`), and using an undeclared service is an error. Built. |
| Session owner (`session-owner`), `evaluate-form`, `evaluate-forms` | The global environment that `eval-buffer` and `M-:` evaluate into | Same behavior; everything evaluated interactively belongs to one always-on owner that `reload-config` leaves alone (see divergences). The entry points are built; the `eval-buffer` and `M-:` commands come later. |
| Editor loop, baton | Command loop, global Lisp lock | Same role. |
| Task | Command, timer, or process callback | Same, except a task may wait in the middle (see divergences). Tasks are part of the kernel. Built for commands and timers. |
| `context-run-with-timer!` | `run-with-timer` | Same; the timer and its callbacks stop when its plugin is turned off. A shared library (`tuna/lib/timers.ss`), not part of the kernel. Built. |
| Job (`job-group-start!`) | Async subprocess or thread | New: works on a snapshot and never touches live buffers; a plugin starts jobs in a job group it owns (`new-job-group`), and a newer job of the same group with the same key replaces the waiting one. A shared library (`tuna/lib/jobs.ss`), not part of the kernel; the kernel only posts each result back to the editor thread. Built (threads). |
| Prompt (`read-string`, `read-from-minibuffer`, `completing-read`) | Same names, via recursive minibuffer | Same direct style. Both readers use the typed prompt handle. `completing-read` returns the chosen candidate's value; `M-RET` returns literal input when `require-match:` is false. Without a completion UI, `RET` requires an exact name when matching is required. Built ([ADR 14](../agents/adr/0014-completion.md)). |
| Completion candidate and table | Completion strings and completion metadata | Explicit records: candidate text, value, identity key, optional category/group; table category, candidate list or input-dependent procedure, optional sort/group/annotation. `strings->candidates` adapts a string list. No hidden string properties. Built ([ADR 14](../agents/adr/0014-completion.md)). |
| Completion session (`CompletionSession`, `current-completion-session`) | Minibuffer-local completion variables and UI-specific current-candidate hooks | One explicit object per prompt: input, category, ordered candidates, selected record, origin command/buffer and revision; selection, exit, insertion, spans and annotations through an interface. Nested reads restore the outer object. No dynamic-variable side channel. Built ([ADR 14](../agents/adr/0014-completion.md)). |
| `completion-service`, `completion-ui-service` | Completion mechanism, `completing-read-function`; Vertico | Separate live engine and presentation slots. The engine matches inline after each input command; the UI rebuilds ordinary prompt-buffer nodes from its revision. The vertical UI shows up to `completion-count` candidates (default 10), highlights with `<mark>`, uses CSS Grid for annotations, and clicks through a shared node keymap. Removing it restores plain prompt keys; replacing it keeps the read and selection. Built ([ADR 14](../agents/adr/0014-completion.md)). |
| `completion-styles`, `completion-category-overrides`, style/annotator registration | `completion-styles`, category overrides, `completion-styles-alist`, Marginalia annotators | Owner-tagged engine registries rather than advice. A style compiles input into a matcher returning spans; the first style producing matches wins. Smart-case substring is built in. Default sort is history recency, length, then name; a table sorter receives plain `(index . text)` pairs in source order, keeping live candidate values out of the pipeline. Annotators run only for shown rows, in the origin buffer, before table fallback. Built ([ADR 14](../agents/adr/0014-completion.md)). |
| Orderless style (`orderless`) | Orderless's `orderless-literal` and `orderless-regexp` | Space-separated components all match, in any order. Each tries a literal substring first, then a valid Gerbil `:std/text/pregexp` expression; invalid expressions stay literal. Uppercase makes that component case-sensitive, otherwise it ignores case. Reports the first span for each component, including overlaps. Starter and demo choose `(orderless substring)` through `completion-styles`; removing the style restores substring. Component dispatch (`!`, `=`, `~`, `,`) is not built. Built ([ADR 14](../agents/adr/0014-completion.md)). |
| Command annotations (`annotations`, package `command-annotations`) | Marginalia's command annotator | The engine's category registry supplies two explicit fields: first reachable key from the origin focus, and first docstring line. CSS aligns them and truncates muted documentation to one line; no padded or propertized strings, category guessing, or advice. Removing the plugin restores M-x's binding-only fallback. Built ([ADR 14](../agents/adr/0014-completion.md)). |
| `execute-extended-command` (`M-x`) | Same | A plugin builds a `command` table from visible command records, reads with history `extended-command`, and runs the choice through `call-command`. Fallback annotations show the first reachable binding in the origin keymaps. No UI is required. Built ([ADR 14](../agents/adr/0014-completion.md)). |
| Prompt handle (`Prompt`) | `minibuffer-setup-hook`, the minibuffer buffer/map and exit functions | An explicit typed interface passed to `setup:`: the prompt buffer, a prompt-local map, typed input, an exit check (#f accepts, a string refuses), and exit with any value. Nodes use the existing buffers contract; caller bindings live on the answer node before the shared prompt map. No dynamic-variable side channels or advice. Built ([ADR 14](../agents/adr/0014-completion.md)). |
| `history:`, `minibuffer-history`, `M-p`/`M-n` | Minibuffer history variables, `previous-history-element`/`next-history-element`, `savehist` | Named, newest-first string lists owned by the minibuffer plugin and saved in one session slot. Accepted answers remove older duplicates; cancel and refused exits add nothing. Navigation returns to the unfinished input. `minibuffer-history-length` is a setting (default 100; #f unlimited; 0 disabled), not a hard cap. Built ([ADR 14](../agents/adr/0014-completion.md)). |
| Minibuffer | Minibuffer, recursive minibuffers | Same: each waiting prompt has its own internal buffer holding its question and answer; only the innermost receives keys. The prompt shows in the minibuffer view nearest the selected view (the bar's, or one pinned inside a split), which is selected while it waits; the previous selection comes back after. `RET` runs `exit-minibuffer` and `C-g` runs `abort-minibuffers`, bound in the keymap of the prompt's buffer, so in another view `RET` is an ordinary newline and `C-g` is `keyboard-quit`, which leaves the question waiting, as in Emacs. `exit-minibuffer` in a prompt that is not the innermost refuses ("Not in the innermost minibuffer"), as Emacs's does. Built. |
| *Help* (`quit-help` `C-h q`) | *Help*, closed with `q` (`quit-window`) | An ordinary buffer shown with `display-buffer`; `C-h q` kills it, which closes a view made for it. `q` is not bound in it yet, though its root node could now carry a keymap. Built. |
| `quit` and the quit key | `quit` signal, `C-g`, `inhibit-quit` | Same names; stronger guarantee (see divergences). |
| Session slots (`context-add-session-slot!`) | `savehist`, `desktop`, `saveplace` | Same purpose, defined by the session contract (not the kernel), kept by the session plugin and stored as plain data in `$XDG_STATE_HOME/tuna/session.ss`, saved while idle and on exit, restored on start. Built: buffers (names, points), the layout (its tree with pins, locks and sizes, the frame and frame marks), and named minibuffer histories. |
| Autosave | `auto-save-mode`, `recover-session` | Same purpose: unsaved buffer text goes to `$XDG_STATE_HOME/tuna/autosave/`. Unlike Emacs, it comes back by itself on start, with the session, for buffers that visit no file (Emacs's `desktop` does not keep their text). Built. |
| `init.ss`, `custom.ss` | `init.el`, `custom-file` | Same roles; `custom.ss` is data, not code, and comes later with a settings screen; what it saves overrides `init.ss`. `init.ss` is found through `--config`, `$TUNA_CONFIG`, or `~/.config/tuna/init.ss`; its code other than `import` and `use-plugin` becomes the plugin `init`, turned on last. Built. |
| `use-plugin` | `use-package`, Doom's `doom!` | Declares a plugin; loading `init.ss` turns nothing on. A `config:` block (like `:config`) is its own small plugin, on while its plugin is on. Built. |
| Plugin options (`use-plugin p key: value`, `defplugin-options`) | `use-package` `:custom`, `defcustom` | A plugin declares each option with a type, default, and documentation, like `defcustom`; `init.ss` gives values as data, like `:custom`. Unlike Emacs, every option is checked against its type when `init.ss` loads, all problems are reported with their lines, and a file with a bad option changes nothing; a changed option replaces only that plugin on reload. Built. |
| Start-up report, `tuna check` | `*Warnings*`, `--debug-init` | One line per plugin: on, failed (and why), or skipped (and what it needs); also in `$XDG_STATE_HOME/tuna/startup.log`, and summarized in the echo area when something failed; `show-config-report` shows the last start-up or reload report. Unlike an error in `init.el`, a failure skips only that plugin. Built. |
| `reload-config`, `tuna reload` | `load-file` on `init.el`, restarting Emacs | Loads `init.ss` again as a trial and turns off, on, or replaces only what changed; a failing new part is undone and the running one turned back on, except that a changed module of your own imported by path has its definitions replaced as soon as it loads. `tuna reload` works from a terminal even when your input plugins are broken. Built. |
| File-system service providers | `file-name-handler-alist` (TRAMP, compressed files) | Same purpose. |

|---|---|---|---|---|
| `defcustom` serves both package options in `use-package :custom` and values changed later through customize or `setq` | Two concepts: plugin options (`use-plugin p key: value`), parameters of one declaration checked when `init.ss` loads, a change replacing the plugin; and settings, scoped runtime values. Settings will use the options' types when they get schemas; the settings screen edits settings, options are edited in `init.ss` | Options must be checked before anything runs, and a changed option must be undoable by replacing one plugin | A ported `defcustom` read only at load becomes an option; one read while running becomes a setting | [ADR 9](../agents/adr/0009-settings-and-scoped-values.md) (amendment 2026-10-13) |
| Renders in its own window or terminal | Renders HTML in a browser tab | Rich UI, remote use | Display code is rewritten | [ADR 7](../agents/adr/0007-rendering-and-transport.md) |
| Buffers are flat text | Buffers are node trees | Real structure instead of text hacks | Magit-, Dired-, agenda-style buffers are rewritten as rich nodes | [ADR 6](../agents/adr/0006-buffers-nodes-and-text-store.md) |
| Keys the window system delivers | Keys the browser delivers; some (`C-w`, `C-n`, `C-t`) never arrive in an ordinary tab | Ordinary tabs must work for remote development | Users rebind those keys | [ADR 7](../agents/adr/0007-rendering-and-transport.md) |

| Display, windows, buffers, and the command loop are C code that Lisp can only customize | A small fixed engine; everything that makes Tuna an editor is a plugin with no special access | Anything Tuna does, a replacement can do | None for ordinary packages | [ADR 12](../agents/adr/0012-kernel-boundary-and-replaceability.md) |

| `C-x 1` (`delete-other-windows`) deletes every other window | `C-x 1` (`frame-to-selected-view`) points the frame at the selected view; the other views stay, and `C-x n w` brings them back | Nothing is lost, and frame marks and tabs keep pointing at their parts | Code that calls `delete-other-windows` to get one window moves the frame instead, or deletes views itself | [ADR 13](../agents/adr/0013-views-layout-and-frames.md) |
| `tab-bar-mode` tabs each hold a window configuration of the whole frame | Tabs are a container kind: a tabbed container can sit anywhere in the layout, and its active tab is the child it last focused | One tree for everything on screen; tabs inside splits and splits inside tabs | Code that switches whole-frame tab configurations moves the frame between tabbed parts instead | [ADR 13](../agents/adr/0013-views-layout-and-frames.md) |
| A frame always shows its whole window tree; narrowing is a separate buffer feature | A frame points at any part of the tree: a container, a view, or a node inside a buffer; the screen shows that part. | The minibuffer and echo area live in a special minibuffer window | They are buffers shown by ordinary views in the layout, locked and pinned in a bar at the bottom; a prompt's view is the selected view while it waits | One mechanism for everything on screen; layout plugins can place them | Code that finds the minibuffer window uses the minibuffer contract instead | [ADR 13](../agents/adr/0013-views-layout-and-frames.md) |
| The minibuffer window shows the echo area while nothing is asked | Two views: the minibuffer's, which takes no space while idle, and the echo area's, which always has its line; a message stays visible while a prompt waits | The two plugins stay independent (either can be off), and each finds its nearest view by itself | None for ordinary code | [ADR 13](../agents/adr/0013-views-layout-and-frames.md) (Stage 3 additions) |
| A frame's minibuffer serves the frame, or a minibuffer-only frame serves several | A prompt or message goes to the minibuffer or echo area view nearest the selected view: walking up, the first in a part pinned beside the way; the bar at the top serves everything, one pinned inside a split serves that split | Different parts of the screen can ask in their own place | Code that names a minibuffer window uses `read-string` and `message` instead | [ADR 13](../agents/adr/0013-views-layout-and-frames.md) |
| `delete-other-windows` keeps side windows; zooming has no notion of what to keep | Zooming the frame keeps pinned parts, by one rule for every container kind: each container on the way up draws the child on the way and its pinned children | Things like the minibuffer, a button bar or a terminal stay while you zoom | None | [ADR 13](../agents/adr/0013-views-layout-and-frames.md) |
| Windows are a fixed tree of splits built into C | Window management is a replaceable plugin; the default is a recursive tree of splits, scrolling strips (Niri), and tabs (i3) | Far more flexible layouts; users can swap the whole manager | Packages that walk the window tree with `window-tree` or `window-child` need the window contract instead | [ADR 11](../agents/adr/0011-window-management-is-a-plugin.md) |
| `unload-feature` is best-effort | Turning a plugin off undoes everything it added, in any order | Reliable reload and disable | Packages must register through their context | [ADR 2](../agents/adr/0002-plugins-contexts-and-services.md) |

| A subsystem cannot be replaced; redefining its functions leaves the state other code holds | Replacing a plugin that fills a service restarts the plugins that use it and restores their saved data (text, points, views); in-memory state such as undo history is lost | Whole subsystems (text store, buffers, layout, renderer) are replaceable while Tuna runs | Undo history and unsaved plugin-built content do not survive a swap | [ADR 2](../agents/adr/0002-plugins-contexts-and-services.md), [ADR 4](../agents/adr/0004-state-ownership.md) |
| `define-key` overwrites one shared keymap | Bindings are entries tagged with their owner | Exact undo; help shows who bound a key | Code that treats keymaps as raw lists changes | [ADR 2](../agents/adr/0002-plugins-contexts-and-services.md), [ADR 8](../agents/adr/0008-input-keymaps-and-command-composition.md) |

| Named-function advice modifies the shared function; local function variables use `add-function` | Same distinction: function advice follows the shared module definition; command advice follows the command registry | Ownership controls removal, not implicit function locality | Use an explicit local extension point when behavior should be local | [ADR 2](../agents/adr/0002-plugins-contexts-and-services.md) |
| Advice ties depend on installation order; `filter-return` receives one Lisp value | Ties use configuration declaration order, then same-owner advice name; `filter-return` receives every Scheme result as an argument and may return any number | Deterministic reload and normal Scheme multiple values | Do not rely on equal-depth reinstallation moving advice; filters accept their target's result arity | [ADR 2](../agents/adr/0002-plugins-contexts-and-services.md) |
| `init.el` runs top to bottom, each form taking effect at once | `init.ss` is loaded first, collecting `use-plugin` declarations; the plugins and your own code are turned on afterwards | A file that fails to load changes nothing; every effect has an owner and can be undone | Code that relies on running at load time moves into a plugin or into your own code | [ADR 2](../agents/adr/0002-plugins-contexts-and-services.md) |
| An error in `init.el` aborts the rest of the file | Each plugin, `config:` block, and your own code turns on separately; a failure is undone and reported, plugins that need it are skipped, and the rest come up | One mistake does not take down the whole configuration | None | [ADR 2](../agents/adr/0002-plugins-contexts-and-services.md) |
| Definitions in `init.el` are global | Definitions in `init.ss` are local to your own plugin (`init`); helpers shared with `config:` blocks go in a module imported by a path relative to `init.ss` | Turning your code off removes its definitions too | Helper functions move to a small module | [ADR 2](../agents/adr/0002-plugins-contexts-and-services.md) |

### Under consideration

Not decided; recorded so they are not forgotten.

- **Undo tree built in**, from persistent text versions (Emacs needs undo-tree or vundo).
- **Highlighting kept as a cache** that survives edits instead of being written into buffer text properties.
- **Folding as per-view state**, so the same file can be folded differently in two windows.
- **Mode line, header line and tab bar as rich nodes** instead of the `mode-line-format` mini-language.
- **Completion filtering as jobs** (typed candidates are decided: see divergences).
- **Resumable debugger**: a failing command waits so you can fix it and continue.
- **Action resolver** in the style of Plan 9's plumber, unifying `ffap`, `browse-url`, buttons, and Embark actions.
- **Several views per node kind** that you can switch between (summary, table, raw), as in Glamorous Toolkit.
