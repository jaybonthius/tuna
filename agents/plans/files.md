# Plan: files

Brief (approved 2026-10-26): [`docs/briefs/2026-10-files.md`](../../docs/briefs/2026-10-files.md). Research: [`agents/research/files/emacs-files.md`](../research/files/emacs-files.md), [`agents/research/files/other-editors.md`](../research/files/other-editors.md). ADR 5 (persistence).

## Invariants

- A text visits the file (visit record on the text: file name, true name, file identity, disk state at last read/save including a content hash, encoding, BOM, line-ending convention, final newline, saved revision); one text per file (true name / identity); buffers show it.
- All file I/O goes through a file service (`files` contract, interface; provider = local disk). No plugin calls the OS for files directly.
- Bytes round-trip exactly: UTF-8 ± BOM editable; uniform CRLF shown as lines and written back as CRLF; mixed endings kept as bytes; final newline kept; anything else (invalid UTF-8, UTF-16, binary by first KiB) opens read-only with an echo-area note. No encoding guessing.
- Saving: temp file in the same folder, fsync, copy mode (owner where allowed), rename, fsync folder; in place after a backup copy when renaming would change identity (hard links, owner not preservable, folder not writable); symlinks save through. Save hooks' errors reported and logged.
- Picker: `C-x C-f` is `completing-read` over two sources, "Recent files" and a `file` table computed from the input (folder listing through the file service), category `file`, annotator (size, modified, already open), and picker keys through the prompt handle (`DEL` deletes one character, `~/` goes home).
- Kernel unchanged. Docs updated as each stage merges.

## Stages

1. **Open and save.** Check Gerbil first (inotify overflow/folder events, folder fsync, chown). `files` contract + plugin: file service and local provider; visiting (`find-file`, `find-file-noselect`, `find-file-hook`, mode hand-off hook for later); the picker; `C-x C-s`, `C-x s`, `C-x C-w`; encodings/line endings/binary as above; unsaved marker in the status line; asking before killing an unsaved buffer and before quitting; `default-directory` per buffer; `before-save-hook`, save takeover hook, `after-save-hook`.
   *As built (2026-10-26, branch `files-1`; report `/home/jay/Code/workbench-gerbil/scratch/files/stage1-report.md`):* package `plugins/files/` (`contract.ss`: `FileSystem` and `Files` interfaces, the `visit` class, hooks, `default-directory`, file-name helpers; `local-disk.ss`: the provider, with a small FFI for realpath, chmod, chown, nanosecond mtime and folder fsync; `encoding.ss`; `picker.ss`; `plugin.ss`). Outside it: `completing-read` `setup:` (completion contract), `buffer-read-only` and kill queries (buffers contract), status-line parts (renderer contract), `kill-buffer` on `C-x k` (view-commands, because of the package-cycle rule). Choices: the visit is kept by the files plugin in a table keyed by text; unsaved = character revision ≠ saved revision; the picker's keys sit on a node wrapping the prompt's answer (the prompt-local keymap is dead under completion, `TODO.md`); a new file's folder is never created; save hooks' failures follow the kernel's `run-hook` (reported, removed, save goes on); kill queries run only on the interactive path. Open: quit does not ask (no quit command); autosave restores file buffers without their visit (stage 4).
2. **Recent files and remembered places.** Session slots; completion sources (named groups in one list), with "Recent files" in the picker.
   *As built (2026-10-26, branch `files-2`; report `/home/jay/Code/workbench-gerbil/scratch/files/stage2-report.md`):* **Sources** in the completion contract: `completing-read` takes a non-empty list of `completion-table`s (one table is the one-source case; every caller updated), and a table gained `title:` (its group heading) and `query:` (input -> the text its candidates are matched against). The engine matches every source with the first style that matches in any of them, keeps each source's own sort, and concatenates in source order; `session-group` falls back to the source's title, so `completion-list` draws the headings unchanged. **Files plugin:** recent files (true names, most recent first, deduplicated, `recent-files-limit` 100, slot `recent-files`), recorded when a file is visited (also an open one again) or written to a new name, pruned of missing files whenever shown; remembered places (true name -> position, `remembered-places-limit` 400, position 1 not kept, slot `remembered-places`), kept on kill, on save (own `after-save-hook` callback) and at session save (the slot's save adds open buffers' positions), restored clamped when a file gets a new buffer. The picker offers "Recent files" only while the input's folder is the starting one (or empty), matched against the name after it, because typing a folder means navigating; `recent-file` (unbound, `M-x`) offers them alone; `C-x C-w` shows only the folder. Restores merge: entries recorded before the restore stay first.
3. **Changes on disk.** Folder watches on a background source, ~100 ms burst absorption, polling fallback, re-check on tab focus and before save, content comparison, own saves ignored; reload by diff as one undoable change keeping cursors, marks and modes; conflict at save (overwrite / reload theirs); deleted/renamed reported; `revert`, `before-revert-hook`, `after-revert-hook`.
   *As built (2026-10-26, branch `files-3`; report `/home/jay/Code/workbench-gerbil/scratch/files/stage3-report.md`):* the file service gained `watch-file` (callback with the file's SHA-256, or #f), `unwatch-file` and `check-watched-files` (any thread). The local disk's watcher (`watcher.ss`) is one source (tuna/lib/background) whose read blocks on inotify on each watched file's folder (close-write, moved-to/from, create, delete, attrib, delete-self, move-self; overflow rescans all), absorbs bursts (100 ms quiet, 500 ms at most), confirms a missing file after 300 ms, and polls folders it cannot watch every `auto-revert-interval` (2 s); `auto-revert-use-notify` off polls everything (both read when watching starts; the source stops when nothing is watched). A reading is (path . size, device, inode, hash) per file, so the editor hears only of byte changes; event-driven paths are always hashed again, because a write within the clock tick keeps size and modification time. The files plugin (`plugin.ss`) checks the file itself on each report: same hash as the visit → only attributes recorded; same bytes as saving would write → recorded as saved; unmodified and `auto-revert` → reload; otherwise `conflict?` on the visit ("changed on disk", status line `* changed on disk`). Reload = `line-diff.ss` (Myers on lines, common prefix/suffix first, one replacement of the middle beyond 4 M steps) applied last-first between undo boundaries; encoding fields updated; `buffer-read-only` follows editability. Saving compares stat (and the hash when it differs, or always under a conflict) and asks overwrite/reload through `completing-read` (reload first). Deleted → saved revision -1 (unsaved). `revert-buffer` (command asks when modified; contract function never asks), `before-revert-hook`, `after-revert-hook`, setting `revert-buffer-function`, setting `auto-revert`. A page script (`web/files.js`, through the page contract, `page-service` optional) posts `/plugin/files/check` on visibility or focus regain. Kernel unchanged.
4. **Autosave for file buffers** in the state folder, restored on start.
