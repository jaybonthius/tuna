# Gap buffer benchmark

This document records the explicit `buffer-content` performance gate. The sole
authoritative local result is `.state/gap-buffer-benchmark.json`; normal tests do
not execute timers, inspect the host, read cumulative allocation, or write a report.

## Method

The runner uses Racket 9.2 CS monotonic wall time, process CPU time, and cumulative
allocation differences. Corpus/store/oracle construction, collection, validation,
hashing, progress output, and report I/O are outside measured regions. Aggregate
rows use one warmup and five fresh samples. Latency rows use 20 warmups and 200
individual samples with nearest-rank p99.

The local trace starts with deterministic 1 MiB ASCII and runs 10,000 insert/
backspace pairs at `modulo(+ (* i 7919) 17) (add1 n)`. In addition to final bytes,
each run checks an independently precomputed rolling checksum over all 20,000
returned change-set fields and intermediate lengths. The ungated long-line row
measures one worst-case EOF locate/resolve query per sample.

## Validation and provenance

`report-validation-errors` checks structural consistency only: exact workload
inventory/order, hashes, sample derivations, identity eligibility, gates, status,
and overall decision. Loading a JSON report cannot prove that its measurements or
oracle executions occurred. Execution provenance comes from the runner performing
in-process flat-oracle comparisons and observing the local-trace rolling checksum
before it writes the report.
