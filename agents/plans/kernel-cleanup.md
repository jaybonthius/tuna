# Plan: kernel cleanup

Owner-approved contract: ADR 12's "Kernel contract" section ([`agents/adr/0012-kernel-boundary-and-replaceability.md`](../adr/0012-kernel-boundary-and-replaceability.md)) and [`docs/briefs/2026-10-kernel-contract.md`](../../docs/briefs/2026-10-kernel-contract.md). Evidence: [`agents/research/kernel-audit-2026-10-12.md`](../research/kernel-audit-2026-10-12.md) and [`agents/research/kernel-contract/`](../research/kernel-contract/) (lane 3 gives per-export verdicts). Behavior must not change: every existing test keeps passing, adjusted only for moved names.

## Steps

Each step is a separate implementer task in its own worktree (AGENTS.md), merged only after the primary agent reads the whole diff for placement and a fresh read-only reviewer checks it against ADR 12. Each task brief names the layer that owns every moved piece.

1. **Mechanical checks first.** Built as `tuna/kernel/boundary-test.ss`, run by `make test`: `tuna/kernel/` may hold only `.ss` files and the baseline; non-test kernel source (`tuna/kernel.ss` and every `.ss` under `tuna/kernel/`, excluding `test-fixtures.ss`) may import only `:gerbil`, `:std`, and kernel modules, may include only checked kernel files, and its hits of ADR 12's forbidden nouns, command-registry names, and plugin names may not exceed the entries in `tuna/kernel/boundary-baseline.sexp`. It is a ratchet: the test fails on any new hit and on any entry larger than what remains, so each later step must delete or lower its entries. Merge review must confirm the baseline diff only removes or lowers entries. Each step, when done, also removes its tag from baseline-steps in boundary-test.ss.
2. **Opaque input.** *Done.* Replace `key-event` in `kernel/loop.ss` with opaque items wrapped in a private queue struct (`queued-input`); `submit-event!` became `submit-input!`, taking any item. `Input` gets `arrival` (queue or interrupt, replaces `quit-event?`) and `resolve!` (replaces `resolve-event!`). Move `key-event` and the browser fields to `tuna/services/keys.ss`; the web plugin builds it; the keys plugin interprets it. Keep `input-pending?` and `discard-input` (ADR 3 lists both); they count and drop only input items, never queued tasks or job results.
   Remove its baseline entries (`step 2`) in `tuna/kernel/boundary-baseline.sexp`.
3. **Commands out.** *Done.* `command`, `context-define-command!`, `define-command`, `defcommand`, `command-entry`, and `command-ref` moved to `tuna/services/keys.ss`, dispatching through new `Keys` methods `define-command!` and `command-entry` (the `keymap-set!` pattern); the keys plugin owns the command table (`global-keys` field `commands`) and registers through `context-add-entry!`, so deactivation still removes a plugin's commands. The kernel's `commands` field and `kernel-commands` are gone. `Input-resolve!` returns `(name . thunk)` or #f; the loop runs the thunk as a task with that name. `current-command-name` became `current-task-name`. The kernel tests resolve items to `(name . thunk)` directly; the registry tests moved to `tuna/plugins/keys-test.ss`.
   Its baseline entries (`step 3`) are removed.
4. **Hooks owned by hook objects.** *Done.* Each hook holds its callbacks (a list replaced under the hook's mutex); the kernel's `hooks` field and `kernel-hooks` are gone. Because module-level hooks outlive a kernel, each callback records the kernel whose plugin added it, and `run-hook` and `hook-callback-names` see only the current kernel's callbacks. `context-add-hook!` and `run-hook` moved from `kernel/hooks.ss` to `kernel/plugins.ss` (they report through `message`); failing callbacks are still removed and reported. New lifecycle hooks: `plugin-activated-hook` (plugin), `plugin-deactivated-hook` (plugin), `service-changed-hook` (service, old provider or #f, new provider or #f) in `kernel/plugins.ss`, announced in order once the outermost activation or deactivation finishes; `task-started-hook` (id, name) and `task-finished-hook` (id, name, how: `returned`, `raised`, or `quit`; exactly once per started task, and a task cancelled before it starts announces nothing) in `kernel/loop.ss`, run on the loop thread while no task runs. Lifecycle callbacks must not activate or deactivate plugins (the call raises and the callback is removed); while the loop runs they can queue a task with `spawn-task!` instead, and while it is stopped they cannot cause a plugin change. The facade no longer exports `make-hook`, `hook::t`, `hook-name-set!`, or `hook-doc-set!`.
5. **Libraries.** *Done.* `tuna/lib/` holds shared libraries that use only the public kernel facade `:tuna/kernel` (plus `:gerbil`, `:std`, and other libraries); callers import them directly. `tuna/lib/timers.ss` (`context-run-with-timer!`, `timer?`, `cancel-timer`) moved unchanged. `tuna/lib/jobs.ss` holds jobs (keying, coalescing, owner cancellation, cleared dynamic environment); the kernel keeps `result-poster`, and its `jobs` field and `kernel-jobs` are gone. `start-job` became `context-start-job!`, which takes the owning context first: each context has its own key -> slot table (a weak, locked module table keyed by context, created on first use and dropped, cancelling its jobs, by `context-defer!`), so keys coalesce per owning plugin. Validity is the target's knowledge: `JobTarget-job-changes-since` became `(job-rebase result revision) => (Maybe :pair)`; the library keeps `exact-revision` and `target-alive` and asks the target for `rebase`. `change`, `span`, and `rebase-spans` moved from `kernel/ids.ss` to the buffers contract (`tuna/services/buffers.ss`), whose `text` implements `job-rebase` with `rebase-spans`. The timer tests moved to `tuna/lib/timers-test.ss`, the `rebase-spans` test to `tuna/services/buffers-test.ss`. `boundary-test.ss` also checks `tuna/lib/`: it may hold only `.ss` files, and library source may import only `:gerbil`, `:std`, `:tuna/kernel`, and library modules.
   Its baseline entries (`step 5`) are removed.
6. **Session slots out.** Move `slots.ss` and the `slots` field next to the session contract.
   Remove its baseline entries (`step 6`) in `tuna/kernel/boundary-baseline.sexp`.
7. **Kernel object private.** Stop exporting `kernel`, `new-kernel`, `current-kernel` from `tuna/kernel.ss`; the web plugin receives an input-submitter closure (as jobs use `result-poster`); tests use a test-only facade. List `tuna/kernel.ss` exports explicitly. Delete exports with no caller (`revision-counter` and friends, `active-plugin-names`, others found by a dead-export search). Move test aids (`kernel/test-fixtures.ss`, `plugins/test-keys.ss`) to a test-support directory.
   Rename dictionary-sense key/keys in the kernel (`entry-table-keys`, the `context-add-entry!` parameter) to name/names. Remove its baseline entries (`step 7`) in `tuna/kernel/boundary-baseline.sexp`, and drop the `test-fixtures.ss` exclusion in `tuna/kernel/boundary-test.ss` once the fixtures move.
   Replace the fresh-kernel helpers (`with-buffers`, `with-keys`, `with-editor`, `with-settings-plugins`, and others) with the single test-support helper, which deactivates its plugins in `finally` so dropped kernels leave no dead hook callbacks behind.
8. **Failure reporting and consumed-seam wording.** Kernel failures go to stderr and a kernel hook; the `Messages` seam stays as the only consumed UI-ish service, with nothing added to it. Reword the `Display` seam comments and doc in `kernel/loop.ss` (render, screen, client, clients), the `Messages` `text` parameter, and the echo-area mentions in `kernel/plugins.ss` and `kernel/state.ss`.
   Fix two reporting bugs found in step 4's review: (a) `(displayln text (current-error-port))` writes the text and the port object to stdout, because `displayln` takes rest arguments (sites in `kernel/plugins.ss`, `kernel/loop.ss`, `tuna/main.ss`); write to stderr instead. (b) `run-hook` catches quit conditions and removes the callback as failed; a quit must propagate, not count as a callback failure.
   Remove its baseline entries (`step 8`) in `tuna/kernel/boundary-baseline.sexp`.
9. **Update docs:** ADR 2/3/8 references where names moved; `docs/overview.md` and `docs/diagrams/kernel-layers.svg` status to built; `docs/emacs-equivalents.md` if any concept changed.
