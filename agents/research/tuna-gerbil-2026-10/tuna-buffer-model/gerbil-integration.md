## Architecture
**Recommendation:** add a private `tuna/text-store.ss` for opaque mutable gap storage and logical text operations; `tuna/editor.ss` for logical editor/document identity, text-buffer membership, properties/overlays/anchors, undo/redo, file state and structural edits; `tuna/view.ss` for view/focus/selection state; `tuna/render.ss` (or `tuna/render/html.ss`) for minimal semantic node vocabulary and HTML dispatch. Keep initial nodes sparse (container, text, cursor/selection/decoration as needed), semantic HTML and sparse styling hooks/design tokens. Rendering dispatch should be an explicit target-neutral node protocol/class method (`render`/visitor) with HTML implementation selected at app boundary; never put HTML elements or tags into editor state. This leaves terminal rendering possible without requiring a second renderer now.

Text-store API should expose logical operations/snapshots/slices/edits and no gap position/capacity. Initial gap is a replaceable private implementation, not public interface/contract. Logical editor may hold multiple ordinary text buffers plus structured content; plain file maps to one text buffer. Keep positions/anchors in logical coordinates, with explicit transform/invalidation behavior on edits. Separate transaction rollback (restore failed operation atomically) from user-visible undo/redo history (successful edits); store-local failure atomicity is not a substitute for editor transactions.

State publication: use a single editor-state owner (worker/serialized command execution) initially, and publish immutable render snapshot or versioned state after accepted commands. Input queue’s single worker gives command ordering; avoid mutating editor state from HTTP threads. SSE currently sends only initial empty body then blocks on shutdown (`server.ss:28–33`); extend session loop to consume state publications and call `patch-elements`, with channel/select or a dedicated publication channel. If multiple SSE clients are supported, broadcast/snapshot semantics must be designed; one consumptive channel alone loses events to competing sessions. Current input queue is unbounded by visible code and carries keydown only; define backpressure and command envelope before heavy editor operations.

Integration files: `build.ss:7–18` add modules in dependency order; `tuna/prelude.ss:3–23` only if a deliberate public API is chosen; `tuna/server.ss:13–51` owns page markup/SSE; `tuna/main.ss:35–49` owns concurrency wiring. `tuna/lib.ss` is currently greeting/port only, not an editor API.
