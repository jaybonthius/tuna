### Error recovery: the editor must never become unusable (owner priority, 2026-10-23)

**The goal, not just the trigger:** one bad command, plugin swap, reload, or plugin bug must never leave the editor unusable or require a restart. The incident below is one instance; treat these as general requirements across the kernel's plugin runtime, the layout, the session, and every default plugin. Probably worth a brief (owner approval) before building, since it touches the kernel's activation rules and several contracts.

- [ ] **Incident 2026-10-23: swapping the text store wrecked the screen.** Evidence in `/home/jay/Code/workbench-gerbil/scratch/swap-text-store-incident/` (broken `session.ss`, server log, screenshot). Owner ran `mixed-buffer`, `swap-text-store`, then `switch-to-welcome-buffer` (all via `M-x`); the result had `*welcome*` and the minibuffer inside the locked bar, the main area collapsed to 1 px, and "Session slot layout failed to save: (Argument 1, pair) PAIR expected" every 2 s over the screen. Reproduced: a swap while the `M-x` prompt is open restores the bar in the wrong order (minibuffer below the echo area, because `add-locked-view` order follows plugin reactivation order); a swap while `*mixed*` is showing replaces it with `*scratch*` (demo buffers are not in the session). Not reproduced: the final step (most likely the layout still treating the minibuffer as selected after the rebuild, so `*welcome*` was placed beside it).
- [ ] **Live swaps and reloads must preserve or refuse.** Swapping a service provider tears down and rebuilds every dependent plugin; whatever the session does not carry (bar order, buffers that are not saved, an open prompt, the selected view) is lost or rebuilt differently. Either carry that state across, or refuse the swap while it is unsafe (for example while a prompt is open) and say why. Applies to every swap and to `reload-config`, not only the text store.
- [ ] **Invariants checked where damage happens.** The layout let an ordinary buffer's view into a locked plugin part. Mutations that would break a structural rule (locked parts hold only their owner's views; at least one ordinary view exists; the selected view is ordinary unless a prompt is active) should be refused with a clear message, leaving state unchanged. Look for the same pattern in buffers, frames, and the session.
- [ ] **A failing command or callback leaves state as it was.** If a command, hook callback, or plugin activation fails part way, the editor should end up in the state before it (or a known safe state), not half-changed. Decide what "transactional enough" means per subsystem.
- [ ] **Never persist a broken state; validate on restore.** The broken layout was written to `session.ss`; restarting with the same state folder would have brought it back. Session restore should validate each slot (the layout's invariants above) and fall back to defaults with a report, so a restart always yields a usable editor.
- [ ] **Errors say what rule broke, once, near the cause.** The only sign was a session-save failure in internal terms, repeated every 2 s and drawn over the editor. Errors should name the broken rule and the action that broke it, be shown once (deduplicated), and never cover the editor.
- [ ] **A way back without restarting.** At least: a command that resets the layout to the default (keeping buffers), and a safe mode or panic key that always works (for example `C-g` from any state, and a way to reach `M-x` even if the bar is broken). Consider "undo the last layout change".
- [ ] **A command log for diagnosis.** The server log records only HTTP requests; this incident's sequence was reconstructed from the minibuffer history. A small plugin (not the kernel) observing the command hooks should log each command run (name, tab, outcome, errors), plugin swaps and activations, and session save/restore failures, with a bounded size.
- [ ] **Test the recovery paths.** A test that runs swaps and reloads with a prompt open, unsaved buffers showing, and several views and tabs, and checks that the editor stays usable (an ordinary view is selected, the bar is intact, the session saves). Also a test that a deliberately broken plugin or command cannot wreck the layout.
