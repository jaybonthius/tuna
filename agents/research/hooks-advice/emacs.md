# GNU Emacs hooks and advice: mechanisms, costs, and lessons

**Recommendation:** keep explicit hooks as the normal package integration seam; implement advice as ordinary function composition with named, inspectable, owner-scoped registrations. Copy Emacs’s composition semantics, not its global mutable-variable representation or debugging accidents.

## 1. Hooks: one list representation, several protocols

**Documented API.** A normal hook is conventionally `something-hook`: functions take no arguments and their return values are ignored. An abnormal hook conventionally ends in `-functions`: arguments and return-value interpretation belong in its documentation. Singular `-function`/`-predicate` denotes one function-valued slot, composed with `add-function`, not `add-hook`. These are conventions, not type enforcement. [Manual: `doc/lispref/modes.texi:35–97`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/modes.texi#L35-L97).

| Runner | Exact protocol |
|---|---|
| `run-hooks &rest hookvars` | Run the named hooks in argument order; each member gets no arguments; return `nil`. |
| `run-hook-with-args hook &rest args` | Call every member with `args`; final return unspecified. |
| `run-hook-with-args-until-success` | Stop on first non-`nil`, return that value; empty/all-`nil` returns `nil`. |
| `run-hook-with-args-until-failure` | Stop on first `nil`, return `nil`; otherwise, including empty, return non-`nil` (not a promised particular value). |
| `run-hook-wrapped hook wrapper &rest args` | Call `wrapper(member, args…)` instead of the member directly; stop on the wrapper’s first non-`nil` result and return it; otherwise `nil`. This is per-member interception, not advice around the whole hook. |

Sources: [manual, `modes.texi:102–145`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/modes.texi#L102-L145); [C runners, `src/eval.c:2883–2991`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/src/eval.c#L2883-L2991). Mode entry uses the specialized `run-mode-hooks`, not bare `run-hooks`.

**Observed storage and ordering.** The hook value remains an ordinary ordered function list. `add-hook HOOK FUNCTION DEPTH LOCAL` orders smaller depths first, default 0; `-100..100` is a convention, not an enforced bound. At equal depth, new members go **before** old members when depth ≤ 0, **after** when depth > 0. A non-`nil` symbol in the legacy DEPTH position means 90. Nonzero depths live separately: the hook symbol’s `hook--depth-alist` property points to an uninterned symbol whose value is a function→depth association list, itself buffer-local when needed. Registration sorts the list; execution does not look up depths. Source comments explain that list membership uses `equal` historically, while depth indexing avoids expensive structural comparisons of large/cyclic functions. [`lisp/subr.el:2311–2399`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/lisp/subr.el#L2311-L2399).

**Idempotence and redefinition.** `add-hook` skips an `equal` member already present: adding it again with a different depth does **not** reposition it. Register a function symbol to observe later redefinitions; storing a closure/function object captures that object. Slightly changed anonymous lambdas may become duplicate registrations. `remove-hook` matches with `equal`, removes the member and its depth metadata, and does nothing when absent. [`subr.el:2338–2478`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/lisp/subr.el#L2338-L2478).

**Buffer-local inheritance.** `LOCAL` makes a local list, initially containing `t`. At the `t` position, the runner executes the current default/global list. This is a splice point, **not** a combined global/local depth sort. A local list without `t` replaces global behavior. Removing the last local member leaves `(t)` and kills the local binding; removing a global member with `LOCAL` does not suppress its inherited global occurrence. Functions marked `permanent-local-hook` can survive major-mode changes. Sources: [manual, `modes.texi:185–237`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/modes.texi#L185-L237), [`eval.c:3010–3061`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/src/eval.c#L3010-L3061), removal above.

**Errors are boundary-specific.** Ordinary runners do not catch member errors: remaining callbacks are skipped and the error propagates; the member stays registered. Command-loop pre/post hooks are exceptional: quit is inhibited, a failing member is removed, and later members continue. The manual calls the error “silenced”; the implementation actually emits `Error in …`, so this does not mean “no diagnostic.” Read the implementation, not the stale C comment suggesting the entire hook is cleared. [Manual, `doc/lispref/commands.texi:73–96`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/commands.texi#L73-L96); [`src/keyboard.c:1893–1977`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/src/keyboard.c#L1893-L1977).

## 2. Modern advice: a chain of callable objects

**Observed representation.** `nadvice.el` defines an **oclosure** (a callable closure with accessible fields) of type `advice`, containing `car` = added function, `cdr` = inner function/chain, `how` = combinator, and `props` = metadata. It copies combinator prototypes to construct wrappers; it does not rewrite the original function’s source. An ordinarily advised symbol’s function cell contains the outer advice object; a macro retains its macro wrapper. Undefined/autoloaded targets keep the chain in `advice--pending` until definition, preserving undefined/autoload behavior. [`lisp/emacs-lisp/nadvice.el:41–82, 247–260, 459–537`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/lisp/emacs-lisp/nadvice.el#L41-L82).

### Combinators, precisely

Let `A` be the added function, `O` the **entire inner chain**, `r` the original argument list, and `v` an intermediate result. `apply` spreads a list into positional arguments. `and`/`or` short-circuit and return values, not coerced booleans.

| Combinator | Equivalent body |
|---|---|
| `:before` | `apply A r; return apply O r` |
| `:after` | `v = apply O r; apply A r; return v` |
| `:around` | `return apply A (O followed by r)`; A may call O zero, once, or repeatedly |
| `:override` | `return apply A r`; O is retained for removal but not called |
| `:before-while` | `(apply A r) and (apply O r)` |
| `:before-until` | `(apply A r) or (apply O r)` |
| `:after-while` | `(apply O r) and (apply A r)` |
| `:after-until` | `(apply O r) or (apply A r)` |
| `:filter-args` | `return apply O (A(r))`; A receives **one list**, returns a replacement argument list |
| `:filter-return` | `return A(apply O r)`; A receives **one return value** |
| `:interactive-only` | `return apply O r`; only interactive-spec composition changes |

`:after` is **not** an unwind/finally clause: it does not run when O exits by error/throw. Likewise `:before-while` returns `nil` if A vetoes, not O’s result. Source is authoritative where prose is loose: [`nadvice.el:66–78`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/lisp/emacs-lisp/nadvice.el#L66-L78); [manual, `functions.texi:2235–2355`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/functions.texi#L2235-L2355). **Version-sensitive:** this HEAD has eleven combinators; Tuna ADR 1 explicitly lists ten, without `interactive-only`. That is a scope discrepancy to resolve in the brief, not an automatic new requirement.

### Registration and redefinition

- **Depth is nesting**, not execution time: lower depth is outermost, default 0; ties are newest-outermost. Thus outer `:before` runs earlier, outer `:after` later, and outer `:override` hides even inner advice. Numeric priorities cannot express every pairwise relationship. [Manual, `functions.texi:2030–2058`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/functions.texi#L2030-L2058).
- **Names** are string/symbol `name` properties, independent of the advice function’s own name. Removal/membership accepts either function or name. `define-advice` can define a named function `TARGET@NAME`. Despite `add-function`’s docstring saying an existing function does nothing, implementation **removes then reinserts** matching name (or function when unnamed): no duplicate, but equal-depth order/properties can change. [`nadvice.el:262–295, 398–407, 590–626`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/lisp/emacs-lisp/nadvice.el#L398-L407).
- **Two layers:** `add-function` modifies a generalized place, e.g. `(process-filter proc)`, a global function-valued variable, `(local 'variable)` with a live forwarding link to its global value, or `(var lexical-variable)`. `advice-add` takes a **symbol** and additionally handles aliases, macros, autoloads, pending definitions, and help text. Simply using `add-function` on `symbol-function` misses those lifecycle services. [Manual, `functions.texi:1915–2040, 2139–2161`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/functions.texi#L1915-L2040); [`nadvice.el:297–322`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/lisp/emacs-lisp/nadvice.el#L297-L322).
- **Normal redefinition preserves advice:** `advice-add` wraps the symbol’s `defalias-fset-function` property. `defalias` invokes that mediator; nadvice substitutes the new inner definition under existing advice, stripping copied stale wrappers. Ordinary `defun` follows this path. Raw `fset` bypasses it and can discard the chain. [`src/data.c:993–999`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/src/data.c#L993-L999); [`nadvice.el:477–537`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/lisp/emacs-lisp/nadvice.el#L477-L537). A previously captured old function object is not retroactively updated.

### Interactive calls, visibility, and cost

**Documented interactive rules:** noninteractive advice inherits O’s interactive specification; interactive advice overrides it. If A’s interactive specification is itself a function, it receives O’s specification and returns the argument list for the **combined command**, not A’s differing `around`/filter signature. Argument reading happens before the composed body. [`functions.texi:2061–2136`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/functions.texi#L2061-L2136).

**Observed inspection/debugging:** `advice-member-p` returns a non-`nil` match, not necessarily `t`; `advice-mapc` visits advice functions and property lists, outermost first, including pending advice. `describe-function` keeps original documentation and lists advice; overrides get an explicit warning. The source still has an unimplemented note to record advice installation locations. Modern printing recognizes `#f(advice …)`, but wrappers and `apply` calls still complicate stacks. This is not wholly opaque: `debug-on-entry` itself uses advice, and trace uses named depth −100 around-advice plus `unwind-protect` to report nonlocal exits. Sources: [`nadvice.el:91–168, 233–245, 509–537, 615–648`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/lisp/emacs-lisp/nadvice.el#L91-L168), [`debug.el:676–716`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/lisp/emacs-lisp/debug.el#L676-L716), [`trace.el:222–257`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/lisp/emacs-lisp/trace.el#L222-L257).

**Cost inference from representation:** an executed chain adds wrapper calls, argument handling, and advice bodies; ordinary before/after chains grow linearly with traversed advice count. Around-advice can multiply calls arbitrarily; override/short-circuit can skip inner work. A target without advice has no nadvice wrapper. This establishes structure, **not a portable timing estimate**; no performance benchmark was run.

## 3. Maintainer rationale and concrete pitfalls

- **Prefer explicit integration.** The manual reserves named-function modification for cases lacking another route: prefer hooks, or a new command plus key remapping. Released packages should try to avoid advice and ask for an upstream hook; Emacs’s own code should generally not advise itself. This is guidance, not an API prohibition or a claim that all advice is bad. Advice is preferable to raw replacement when modification is unavoidable because it is listed and undone. [`functions.texi:2163–2200`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/functions.texi#L2163-L2200); [`tips.texi:195–210`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/tips.texi#L195-L210).
- **Why replace `defadvice`?** Monnier and Sperber explain that non-core features were rarely used, and even more rarely used properly: their design did not match actual usage. Argument-access machinery conflicted with lexical scope; ordinary functions reused compilation and argument passing instead of inventing special constructs. Nadvice arose from composing several functions in one variable. See their primary historical account, *Evolution of Emacs Lisp*, §4.7, pp. 74:15–16, [DOI](https://doi.org/10.1145/3386324), [author-hosted PDF](https://www.deinprogramm.de/sperber/papers/hopl-4-emacs-lisp.pdf), [readable copy](https://dokk.org/library/evolution_of_emacs_lisp_2020_acm). The manual additionally explains eliminating separate enable/activate states, `ad-do-it`, and `ad-return-value`: [`functions.texi:2358–2447`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/functions.texi#L2358-L2447).
- **A real user failure:** Kaushal Modi reported that region/whole-buffer advice made `C-M-x` evaluate the whole buffer instead of a defun. Monnier warned that around-advice affects **all callers**, recommending changing interactive arguments without changing function semantics. [Monnier, 2016-02-11](https://lists.gnu.org/archive/html/help-gnu-emacs/2016-02/msg00159.html); [Modi’s follow-up](https://lists.gnu.org/archive/html/help-gnu-emacs/2016-02/msg00163.html). The lesson is the command/function distinction, not that the suggested snippet suits every command.
- **Ordering and invisibility:** equal-depth installation order changes nesting; reinstallation can change it again; overrides/filters can invalidate another extension’s assumptions. These are consequences of documented semantics, not evidence of prevalence. Ordinary normal hooks are also intended to be order-independent: the manual calls order dependencies “asking for trouble” ([`modes.texi:198–219`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/modes.texi#L198-L219)). Help makes advice discoverable, but the target source does not reveal installed modifications.
- **Known semantic edge, not just inconvenience:** HEAD’s tests explicitly mark innermost-around and filter-args interactions with `called-interactively-p` as expected failures. Nadvice has stack-skipping workarounds. [`test/lisp/emacs-lisp/nadvice-tests.el:141–162`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/test/lisp/emacs-lisp/nadvice-tests.el#L141-L162); [`nadvice.el:628–648`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/lisp/emacs-lisp/nadvice.el#L628-L648).
- **Coverage and signature traps:** direct C calls to primitives bypass advice; primitives used by advice machinery can recurse infinitely when advised; inlined/compiler-rewritten calls and already-expanded macros bypass the named boundary. These are documented limits, not an omnipotent “any function” facility ([`functions.texi:2189–2200, 2449–2478`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/doc/lispref/functions.texi#L2449-L2478)). A concrete source criticism remains in SOCKS: its `open-network-stream` override is called “a terrible idea” and historically signature-incompatible ([`lisp/net/socks.el:328–336`](https://github.com/emacs-mirror/emacs/blob/541f693ca2e8de166cfe52c39bbfc497142215e9/lisp/net/socks.el#L328-L336)).

## 4. What Tuna has and lacks

Observed Tuna baseline: **`57a2b4536cd371ffcf6701563019cd00364bdec6`**; [`tuna/kernel/hooks.ss:34–92`](../../../tuna/kernel/hooks.ss), [`tuna/kernel/plugins.ss:174–225`](../../../tuna/kernel/plugins.ss). Each hook owns callbacks; kernel/owner/name identifies one registration; depth then original serial determines order; replacement keeps serial. Receipts remove exact registrations, and named callback syntax looks up the live binding. This is stronger lifecycle ownership than Emacs, not a missing feature.

| Difference from Emacs | Importance for the brief (inference) |
|---|---|
| Only variadic broadcast `run-hook`, discarding values; no until-success/failure | Important for future handler/veto protocols. Do not treat a notification as an undocumented request/response chain. |
| No `run-hook-wrapped` equivalent | Relevant to the profiler’s per-callback measurement; advice around a whole hook cannot identify individual callback costs. Consider a generic interception seam, not profiler-shaped kernel data. |
| No buffer-local inheritance, `t` marker, mode-change permanence | Context-scoped callbacks matter eventually; buffer semantics belong to the buffers/modes package, not a buffer-aware kernel. No need to reproduce `t`. |
| Same-depth oldest-first uniformly; same-name replacement can change depth | Deliberate improvement over Emacs’s sign-dependent hook ties; document rather than claiming identical `add-hook` semantics. |
| Every ordinary callback error removes/reports it and continues | Matches the *special command-loop* policy, not general Emacs hooks. Appropriate for notifications; silently continuing a future veto/handler chain could authorize an operation after a failed validator. |
| No Emacs-style raw hook-variable `let`/`setq` or equality-based public removal | Not a portability gap worth copying; retain object identity, named ownership, receipt cleanup, and snapshot iteration. |

## Validation and limits

Read the requested ADRs, equivalents rows, profiler brief, implementation, and prior notes; no source changes or Tuna process started. A capped smoke experiment ran **installed Emacs 30.2, not HEAD**, using `systemd-run --user --scope -p MemoryMax=8G -p MemorySwapMax=0 timeout 45 emacs -Q --batch --eval …`. All assertions passed: hook duplicate/depth non-update, first-success stopping, local `t` and local removal, advice-preserving `defun`, membership/removal, and ordinary hook error propagation without callback removal. HEAD-only oclosure/interactive-only claims are source-verified, not execution-tested. No benchmark or package-frequency claim is made.

## Implications for Tuna

1. **Keep the approved owner-scoped hook model.** Preserve late-bound named callbacks, receipt cleanup and registration identity. Correct the equivalents description: failure isolation and equal-depth ties are intentional divergences from ordinary Emacs hooks.
2. **Name the protocol, not merely “a hook.”** Specify arguments, result semantics, error/quit policy and context. Add first-success/veto runners only with concrete consumers; a failed validator must not become implicit approval. Keep broadcast notifications distinct.
3. **Use ordinary function composition for the ten approved advice combinators.** Keep an identifiable base definition plus removable named layers; do not reproduce `defadvice`’s separate activation/compiler language. Resolve whether interactive-only behavior belongs in command metadata rather than silently extending ADR 1.
4. **Make redefinition a tested installation path.** Define which command/service/exported-binding operations replace the base while preserving advice. Removing advice must reveal the **latest** base. State explicitly what happens to captured function values and optimized calls; never promise universal interception.
5. **Show the effective chain.** Inspection should expose target, owner, name, source, combinator, depth and actual nesting order; retain the original documentation and clearly mark overrides. Define tie/replacement behavior explicitly and test mixed before/after/override chains, not just registration order.
6. **Keep command invocation separate from function execution.** Advice that customizes prompting must not accidentally change noninteractive callers. Avoid detecting interactivity by inspecting stack shape.
7. **Prove profiling without embedding it.** The optional profiler needs whole-call around-advice with unwind protection, plus a way to identify individual hook callbacks. Measure disabled and enabled overhead in Gerbil; do not import Emacs timing assumptions. Context-local integration belongs outside the kernel, and any new generic kernel seam needs ADR 12’s justification.
