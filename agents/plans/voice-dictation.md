# Plan: voice dictation

Brief: [`docs/briefs/2026-10-voice-dictation.md`](../../docs/briefs/2026-10-voice-dictation.md) (model decided 2026-10-23: nemotron-3.5-asr-streaming-0.6b). Binding: `/home/jay/Code/workbench-gerbil/gerbil-parakeet` (local install at `.install-check/local`, models in `.deps/models`); patched parakeet.cpp at `/home/jay/Code/parakeet.cpp` branch `grammar-constraints`. Both local and unpublished; reference them by absolute path through a plugin option / make variable, never vendored.

## Invariants

- Parakeet never runs in Tuna's process (its calls block the whole Gambit VM). The worker is a separate executable; Tuna speaks to it over pipes.
- The browser only captures and sends audio, and starts or stops capture when the server says; it never names a command (ADR 7). Audio needs HTTPS or localhost.
- Audio bypasses the editor thread: web plugin → voice plugin → worker pipe, on their own threads. Only recognized text becomes an editor task (a job result / posted task), applied at point when it arrives (as built; see below).
- Streaming text is append-only (`parakeet_capi_stream_feed` returns newly finalized text); no provisional replacement in this work.
- Placement (owner, 2026-10-23: the web plugin must not know about microphones): page contract (`plugins/web/contract.ss`, provided by the web plugin: `add-script`, a plugin-owned POST address receiving a client's bytes off the editor thread, a one-time per-client instruction after its next screen); microphone contract and plugin (`plugins/microphone/`: page script, its address, start capture on a client with a chunk callback, stop; requires the page service); voice contract and plugin (`plugins/voice/`: `voice-start!`, `voice-stop!`, `voice-dictate`); worker in `plugins/voice/worker/`. Subprocess handling stays private to the voice plugin until a second user needs a library. The kernel is unchanged.
- `make` and `make test` never need parakeet or models; plugin tests use a fake worker. `make voice-worker` builds the real one with `parakeet-compile`, `OMP_WAIT_POLICY=PASSIVE` set by the worker.
- Docs updated as each stage merges (overview, Emacs table, roadmap, brief/plan status).

## Stages

1. **Worker.** Reads float32 LE mono 16 kHz PCM from stdin, feeds `asr-stream-feed`, writes one JSON line per non-empty result (`{"text":…,"eou":…}`), finalizes on EOF; strips `<xx-YY>` language tags. Model path and language as arguments. Check: piping `speech.f32` in 100 ms chunks prints the expected text faster than real time with both models.

   **As built** (2026-10-23, branch `voice-1`). `plugins/voice/worker/worker.ss`, built by `make voice-worker` to `.gerbil/bin/tuna-voice-worker`; `make voice-worker-check` runs `check.sh` (paced and full speed). Protocol: `tuna-voice-worker MODEL [LANGUAGE]`; stdout lines `{"ready":true}` after loading, `{"text":"…","eou":bool}` per feed that finalized text or an end of utterance (text keeps the model's leading space; it may be empty when `eou` is true; pieces can split words, "Pho" + "ebe"), `{"done":true}` after EOF and finalize, or `{"error":"…"}` and exit 1. Each stdin read is fed at once; a read that splits a sample keeps its bytes for the next. The worker's preinit entry re-executes it with `OMP_WAIT_POLICY=PASSIVE` (and no `GOMP_SPINCOUNT`) unless already so, because the installed `parakeet-compile` predates the binding's own startup glue, and gives back the CPUs it started with before loading, because Gambit pins its thread to one CPU and the inference threads inherited that (full speed went from 6.4 s to 2.3 s). gxc writes compiled modules into `GERBIL_PATH`, so the build compiles against a copy of the install's static modules in `.gerbil/voice-worker/`.

   Measured on `speech.f32` (7.4 s), 100 ms chunks (1600 samples, 6400 bytes), page cache warm, launched without `OMP_WAIT_POLICY`:

   | | nemotron 0.6b (default) | realtime_eou 120m |
   |---|---|---|
   | load (start to ready) | 0.37 s | 0.08 s |
   | full speed, first audio to done | 1.9 s (3.9× real time) | 1.2 s (6.4×) |
   | paced: first text | at 1.0 s of audio (speech starts at 0.5 s) | at 0.9 s |
   | paced: word end to its text | 0.1–0.35 s, about 0.2 s typical; a line every 0.3 s | 0–0.3 s, about 0.1 s typical |
   | paced: last text / done after last audio | 0.07 s / 0.13 s | before / 0.04 s |
   | end of utterance | never reported, even after 3 s of silence; its final "." arrives only at finalize | `eou` 0.5 s after speech ends |

   The brief's comparison (nemotron 7.2 s for 7.4 s including load) was measured on one pinned core; the worker takes 2.3 s including load. Idle CPU while waiting for audio is zero. For stage 3: EOF ends the worker, so "kept warm" across dictations needs a protocol addition or a restart per dictation (0.4 s with nemotron, warm cache); undo grouping cannot rely on EOU with nemotron, so group by pause.
2. **Page machinery and microphone.** The page contract in the web plugin (generic; no audio), then the microphone plugin using it: AudioWorklet capture at 16 kHz mono (resampling in the page if the context won't run at 16 kHz), started and stopped by a one-time per-tab instruction like the clipboard copy; permission-denied and missing-API reports to the echo area. Check: a test page records chunks; Chrome and Firefox capture.

   **As built** (2026-10-24, branch `voice-2`). Page contract `plugins/web/contract.ss` (service `page`, startup tier, provided by the web transport): `(add-script "file.js")` puts a plugin's ES module in every page's head after the input module, served at `/js/<n>/<sha256>/<file>` with modules beside it under the same prefix (an AudioWorklet's), until the plugin turns off (a page that already ran it keeps it until reload); `context-add-page-address!` hands each `POST /plugin/<plugin>/<name>` carrying a `Tuna-Tab` header of a tab the transport knows (Host/Origin checked, at most 1 MiB) to the handler with the tab's client and the body bytes, on the request thread; `page-instruct!` queues, per tab, an element appended to the body after its next screen whose `data-init` is `@ACTION(JSON.parse(el.textContent)); el.remove()`. The clipboard copy keeps its own code (TODO). Microphone: `plugins/microphone/` (contract `microphone-start!` with chunk and failure callbacks, `microphone-stop!`); page script `frontend/microphone.ts` and `frontend/microphone-worklet.ts`, built by `make assets` into `web/`. Chunks are posted one at a time, so they arrive in order; what queues meanwhile goes in one post. Problems posted: insecure, unavailable, denied, no-microphone, error with the error's name. Checked in Chrome 146 headless with a fake device playing `speech.wav`; Firefox not checked.
3. **Voice plugin.** `voice-dictate` toggle (`C-c v` in the demo; `C-g` stops), marker at point, worker lifecycle (started on first use, kept warm, stopped with the plugin), insertion of each line at the marker with one undo group per utterance (EOU) or per pause, echo-area status. Tests with a fake worker: text arrives at the marker; typing above moves the marker; stop flushes; turning the plugin off kills the worker. Browser check with real speech (or `speech.wav` played into the page's audio graph).

   **As built** (2026-10-24, branch `voice-2`). `plugins/voice/` (contract `voice-start!` with a text callback, `voice-stop!`, `voice-listening?`; plugin options `worker`, by default this checkout's `.gerbil/bin/tuna-voice-worker`, `model`, nemotron, and `language`, `""`). Not kept warm: each listening starts its own worker (EOF ends it; about 0.4 s, hidden behind the microphone's start), stopping stops the microphone and closes the worker's input so its last words arrive, a worker not done 15 s later gets SIGTERM, and turning the plugin off kills it. Audio goes request thread → a writer thread (mailbox) → the worker's stdin; a reader thread posts each JSON line through the loop's result poster. Undo: pieces less than 1 s apart with no other change between join one group (`undo-amalgamate!`). A piece's leading space is dropped at a line start or after whitespace. *Changed 2026-10-24 (owner, branch `voice-at-point`):* no marker; each piece goes in at the selected view's point when it arrives, as self-insert does, leaving point after it; the pause group also requires the same text, unchanged since the last piece, so a typed character between pieces starts a new group; with no text at point the piece is dropped with an echo-area note. `C-g` stops through `before` advice on `keyboard-quit`. The demo binds `C-c v` (the renderer swap double moved to `C-c V`); the starter does not declare voice, since it needs the worker and a model. Browser check: the words of `speech.wav` appeared in `*scratch*` a few at a time over about 7 s and `C-c v` stopped it (`/home/jay/Code/workbench-gerbil/scratch/voice/stage23-report.md`).
