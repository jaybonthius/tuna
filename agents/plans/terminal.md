# Plan: terminal

Brief (approved 2026-10-27): [`docs/briefs/2026-10-terminal.md`](../../docs/briefs/2026-10-terminal.md). ADR 18 (helper processes and a mirror); ADRs 15 (scroll state), 17 (memo and sources), 12 (small kernel), 5 (persistence). Research: [`agents/research/terminal/`](../research/terminal/).

**Reference implementation: ghostel** (`/home/jay/Code/ghostel`, `dakra/ghostel@42de3eb`, an Emacs terminal on libghostty-vt). Before designing a behaviour, read how ghostel does it (`lisp/*.el`, `src/*.zig`) and follow it unless Tuna's model (browser, helpers, nodes) gives a reason not to; record any divergence in the stage's notes. Its `defcustom`s are the checklist for settings.

## Invariants

- **Configurable.** Every behaviour a user might want differently is a setting or plugin option with ghostel's default unless noted: shell and arguments, `TERM`, environment, scrollback size, redraw timing, buffer naming, kill-buffer-on-exit, query-before-kill, OSC 52 copy, key exceptions, initial input mode, copy-mode fast exit, scroll-on-input, saved screen for reboots (on), shell integration, palette.
- **Placement.** `gerbil-libghostty` (its own repository) is the binding; the helper is a Gerbil program in `plugins/terminal/`; the plugin owns the terminal node, keymaps, hooks, drawing and the session slot. Nothing in the kernel. Other plugins see terminals only through `plugins/terminal/contract.ss` (hooks with the terminal as the first argument). Consumers that act (clipboard, notifications, status) are separate plugins or the existing owners of those concepts.
- **Drawing.** A terminal node's items are its rows (scrollback plus active screen); each row is memoized and compared by value (ADR 17); styled runs become spans; palette colours are CSS variables in the plugin's `tokens.css` (first 16 from the theme), exact colours pass through. The alternate screen shows a fixed grid with no scrollback items. Row identity survives trimming; reflow and clear start a new generation, re-anchoring each tab's scroll on its top row.
- **Threads.** A job per terminal reads the socket and posts byte chunks (`coalesce: 'queue`); the editor thread feeds the mirror and drains effects. Never block or call back into Tuna while holding a terminal lock (ghostel #689, #758).
- **Persistence.** As ADR 18. Helper list in a session slot; snapshots in the state folder, mode 0600.
- Docs updated as each stage merges (overview, `docs/emacs-equivalents.md` rows for vterm/ghostel concepts and divergences, roadmap, this plan, the brief's status).

## Stages

1. **The binding** (worktree of `gerbil-libghostty`). Pin a current Ghostty commit (at least `b7207b2ef`, for program status). Cover the libghostty-vt C API idiomatically, beyond the old Racket parity: rows by screen position as detached styled rows without moving the viewport; total, scrollback and scrollbar reads and the other direct data reads; every settable option (palette, colours, scrollback limit, cursor, kitty storage); every effect (semantic prompt, reset, render hold, program status, clipboard read as a synchronous policy answer); unknown OSC as well as APC; dirty-row iteration; search; selection gestures; viewport scrolling; native paste; compression. Tests per family; update `ghostty.md`, `PARITY.md`, README. Settle how Tuna depends on it (`gerbil deps`, native build, no absolute paths that break when moved).
   *As built (2026-10-27, gerbil-libghostty `e2f51ca`; report `/home/jay/Code/workbench-gerbil/scratch/terminal/stage1-report.md`):* pinned Ghostty `b58ef1d67` (last on Zig 0.16; includes OSC 7501). Direct reads, every option, every effect (semantic prompt, program status with native `?` reply, clipboard-read policy, resize request, reset, render hold, unknown OSC and APC with terminator), `terminal-copy-rows` (any scrollback+active range as detached styled runs, viewport untouched), `terminal-copy-changed-rows!` (changed rows, rows scrolled into history, cursor; shares change tracking with full frames, so one per terminal), absolute row numbers with generations (a new generation when one write exceeds the scrollback limit, on reflow, reset, CSI 3J), search, selection gestures, viewport scrolling, native paste, compression. 147 tests. 160×48 whole screen: 628 MB → 12.9 MB per 100 copies; changed rows only 2 MB. Packaging: `make` stages the native library under `GERBIL_PATH` with a relative rpath; depend through `gerbil pkg link` to the local checkout until it is published. `ghostty_sys_set` stays unbound (process-global). Close searches and gestures explicitly.
2. **A terminal that survives restarts.** Helper (pseudo-terminal spawn, detach, socket, snapshot, stream, exit); `terminal` contract and plugin: `M-x terminal`, terminal node and row drawing, scrolling, resize to the smallest view, semi-char and char keymaps, `C-q`, title → buffer name, OSC 7 → `default-directory`, bell hook, kill and exit behaviour, session slot and reconnect after restart and plugin swap. Acceptance: vim, htop and a long `seq` in the browser; restart Tuna mid-output and the terminal comes back exactly.
   *As built (2026-10-27, branch `terminal-2`; report `/home/jay/Code/workbench-gerbil/scratch/terminal/stage2-report.md`, screenshots in `scratch/terminal/stage2/`):*
   - **Placement.** All in `plugins/terminal/` (package `tuna/plugins/terminal`); the kernel did not change. `io.ss` (system calls behind Gambit raw devices: fork a program onto a pseudo-terminal in its own session, resize, wait, signal its group, private Unix sockets checking the peer's user id), `protocol.ss` (frames), `helper.ss` (the helper, built as `.gerbil/bin/tuna-terminal-helper`), `connection.ss` (starting a helper, the connection), `keys.ss`, `screen.ss` (rows as nodes), `contract.ss` (vocabulary only: the `terminal` class, `terminal-buffer`, `-title`, `-directory`, `-exit-status`, and the hooks `terminal-title-hook`, `terminal-directory-hook`, `terminal-bell-hook`, `terminal-exit-hook`, each with the terminal first), `plugin.ss` (the `terminals` plugin: `terminal` was taken by the contract's class, as `buffers` is to `buffer`), `frontend/terminal.ts` (the page script), `tokens.css`, `rules.css`, `terminfo/xterm-ghostty.terminfo`. The plugin requires commands, input, settings, buffers and session; optional: layout, minibuffer, editing, files, page. It imports only contracts, the kernel facade, `tuna/lib/` and gerbil-libghostty. Declared before `layout` in `starter/init.ss` and `demo/init.ss`, so its session slot restores the buffers before the views that show them.
   - **Build.** `make deps` links gerbil-libghostty (`GERBIL_LIBGHOSTTY`, default the local checkout) and builds it; `make` compiles the terminfo into `.gerbil/terminfo` and builds the helper statically against the staged libghostty-vt (RUNPATH `$ORIGIN/../lib/gerbil-libghostty/native/lib`), which needs the binding's own `native/` headers (found through `.gerbil/pkg/gerbil-libghostty`).
   - **Helper.** Started as `setsid -f [systemd-run --user --scope --collect --unit tuna-terminal-ID] tuna-terminal-helper --socket … -- PROGRAM`, the scope when Tuna's own cgroup is a `.scope` (the `leave-scope` option: auto, always, never). It calls `setsid`, drops its standard ports (stderr to `ID.log` beside the socket, removed when empty), resets SIGCHLD (Gambit reaps every child otherwise), forks the program (termios as ghostel: IUTF8, no IXON, DEL erases), and feeds a libghostty terminal with continuation tracking on. It answers the program's queries itself (it is always there); the mirror replies to nothing. One Tuna at a time: a second gets `refused "busy"` and the plugin retries every 100 ms, which covers a swap whose old connection is still closing. A slow Tuna holds the program back (more than 4 MiB queued stops reading). It ends once its program has ended and a Tuna sent `exit-ack`, or after `kill` (SIGHUP to the group, SIGKILL a second later). Sockets live in `$XDG_RUNTIME_DIR/tuna/terminals/` (0700, checked), the `socket-directory` option overriding.
   - **Mirror and rows.** A job per terminal (`job-group-start!`, coalesce queue) waits for the socket, connects, and posts the connection, then each batch of frames; the snapshot becomes the mirror (`snapshot-bytes->terminal`), output is fed to it on the editor thread, and its handlers only queue effects. Rows are `terminal-row` nodes (one item each) under `terminal-rows` blocks of 64, so adding or trimming rows changes one block; `terminal-copy-changed-rows!` gives the changed viewport rows and the rows frozen into history (re-copied with `terminal-copy-rows`); a new generation (or a new mirror) copies every row again into new nodes. A row's attributes are its runs (plain vectors) and the cursor on it, set by value. The cursor is a span inside its run. Palette colours are 768 generated classes naming `--terminal-color-N` (Ghostty's default palette in `tokens.css`; a theme replaces the first 16); RGB passes through as `--terminal-run-foreground` and friends in a `style` attribute.
   - **Views.** A view follows output while it is where the plugin last put it at the bottom, or a browser measured the last row in view; otherwise it stays put. Typing scrolls back to the bottom (`terminal-scroll-on-input`). The alternate screen swaps the root's children to the alternate store (a grid of the screen's rows, no scrollback), and the primary rows come back intact.
   - **Size.** The page script measures each terminal element's view (ten hidden cells give the cell size) and posts all of a tab's measurements to `/plugin/terminals/size` when they change, or, at most once a second, while a terminal is not the size measured (`data-size`), which covers a restarted Tuna. The terminal takes the smallest view showing it; a resize sends `resize` then `snapshot-request`, and the helper's snapshot replaces the mirror, so output written for one size is never parsed at another.
   - **Restart, swap, reload.** The `terminals` session slot (version 1) lists `(ID SOCKET BUFFER-NAME INPUT-MODE VIEW-IDS)`; turning the plugin off closes connections and kills its buffers but never the helpers; restoring connects again (once the editor loop runs: a restore at start-up waits for the first task) and shows the buffer again in the saved views (for a swap; after a restart the layout does it by name).
   - **Tests** (`plugins/terminal/tests/`, 20 cases): protocol frames; key names and encodings; rows, OSC 7 parsing and the environment; a real helper (snapshot then output then exit, one Tuna at a time and the screen back on reconnect, kill); the plugin with real helpers (a shell's rows, title/folder/bell hooks and title renaming, exit kills the buffer and the helper, a restarted Tuna gets the same screen and output goes on, turning the plugin off and on reconnects, killing the buffer ends the helper, the alternate screen). Every helper is stopped by its pid; no orphans after `make test`.
   - **Divergences from ghostel** (also in `docs/emacs-equivalents.md`):
     - Terminals outlive Tuna (the point of ADR 18): quitting Tuna leaves helpers running and asks nothing; ghostel SIGKILLs its children on `kill-emacs-hook` and asks first (`kill-emacs-query-functions`).
     - The helper, not the mirror, answers the program's queries; OSC 4/10/11 colour queries and the colour-scheme report (`CSI ? 996 n`) went unanswered until stage 3, which tells the helper the theme's colours.
     - Redraw: within `terminal-immediate-redraw-interval` (0.05) of a key, or after 100 ms without output (`terminal-adaptive-fps`), the rows are copied at once; otherwise at the next `terminal-timer-delay` (0.033) tick. ghostel's adaptive delay is a 16 ms timer, not immediate. Hidden terminals are still copied (ghostel defers until shown).
     - Keymaps: ghostel's key list, with `C-i`, `C-m`, `M-[`, `M-O` bound too (the browser has no TTY escape decoding, and `C-i` and `C-m` are their own keys), `SPC` bound explicitly (no `self-insert` remap) and `ESC ESC` not (TTY only). The exceptions are the `keymap-exceptions` plugin option, read when the plugin turns on, where ghostel's `:set` rebuilds the map. `C-q` asks "Send key:" in the minibuffer, as ghostel's `read-event` prompt does.
     - Names: `*terminal*`, `terminal-new` for ghostel's prefix argument (Tuna has no prefix arguments yet; numbered instances are not built); `terminal-buffer-name-function` takes `'title` or `'directory` ("*terminal: TITLE*"), data rather than a function. The title came to the status line in stage 3.
     - The bell runs `terminal-bell-hook` and does nothing else (ghostel's `ghostel-bell-functions` default is `ghostel-ding`; Tuna has no ding). `terminal-exit-hook` gets the terminal and the status, where `ghostel-exit-functions` get the buffer and an event string.
     - `INSIDE_TUNA=terminal` stands for `INSIDE_EMACS=ghostel`; no shell integration yet (stage 4). OSC 7 sets `default-directory` for local hosts only (no TRAMP).
     - `query-before-killing` `auto` reads the shell's terminal foreground group from `/proc/PID/stat` (the helper holds the master, so no `TIOCGPGRP`), or OSC 133 between C and D.
     - Clicks in a terminal did nothing until stage 3.
   - **Open:** reboot revive (stage 5); a helper killed by a signal leaves its socket, and its terminal comes back as "[Terminal helper gone]"; removing the plugin from `init.ss` leaves its helpers running with no one to see their exit; each resize sends a whole snapshot and copies every row again; Kitty key releases (no key-up from the browser).
3. **Copy, line mode, mouse, clipboard, links.** Copy mode (frozen, editing keys, `RET` copies, fast exit), line mode, mouse modes and wheel routing, selection, bracketed paste, OSC 52 copy into the kill ring and the browser clipboard, OSC 8 links, the close-tab question in a plain tab.
   *As built (2026-10-28, branch `terminal-3`; report `/home/jay/Code/workbench-gerbil/scratch/terminal/stage3-report.md`, screenshots in `scratch/terminal/stage3/`):*
   - **Placement.** All in `plugins/terminal/` again; the kernel and every contract are unchanged. New private modules: `copy-text.ss` (rows as one text, positions, copying without wrap line ends) and `links.ss` (finding URLs and file references, putting links into runs, where a link leads). The plugin now also imports the renderer contract (`context-add-status-line-part!`) and declares `renderer-service` optional, and imports more of the editing (`kill-new`, the region, `set-temporary-region!`), files (`find-file-noselect`) and web (`page-instruct!`) contracts. The helper protocol is version 2 (a `colors` frame); helpers from stage 2 are reported as from another version.
   - **Grid.** Every grapheme outside ASCII is an inline block exactly 1ch or 2ch wide, as libghostty sizes it, so glyphs from fallback fonts (braille, box drawing, icons) keep btop's columns; runs fill the row's height, so backgrounds leave no gaps. Fira Code Nerd Font is Tuna's monospace font (`(stylesheets fonts)`).
   - **Copy mode** (`C-c C-t`; `terminal-readonly-fast-exit`, `terminal-mark-activation-input-mode`, `terminal-mouse-drag-input-mode`). A frozen read-only *copy*, not the rows in place: Tuna's motion, mark and kill-ring commands work in the selected view's one focused text node, a region cannot span nodes, and rows are nodes without text. Entering copies the screen's rows (scrollback included) into a text node that replaces the root's children, one line per row, with the rows' palette foreground colours and links as highlights; the buffer is read-only; every view keeps the rows it showed, point at the cursor. Output goes on into the mirror; the rows are drawn again on leaving, and no resize happens meanwhile. `M-w`/`C-w` copy the region without the line ends that only wrap and without trailing spaces (and leave, with fast exit), `RET` opens a link at point or copies the region and leaves, any typing key leaves and goes to the program, `q` and `C-g` leave, `C-y` and `<paste>` leave and paste, `M->` goes to the cursor. `C-SPC` in semi-char mode enters it with the mark at the cursor. A view that comes back to the buffer focuses whatever text the mode has now.
   - **Line mode** (`C-c C-l`; `terminal-line-mode-history-size`, `terminal-initial-input-mode 'line`). The input is a text node in a `terminal-line-input` node placed after the cursor's row (the row store's one extra node) and drawn over the rest of that row from the cursor's column; editing is Tuna's; `RET` sends it and an encoded Return, `S-RET` a literal newline, `M-p`/`M-n` history, `C-c C-c` drops it and interrupts, `C-d` on an empty line sends end of input; leaving hands the input to the program unsent. The alternate screen pauses it, back in semi-char mode, until the program leaves it; it comes back after a restart.
   - **Mouse.** The page script reads each terminal's `data-mouse`: `program`/`program-motion` while the program tracks the mouse in semi-char or char mode (presses, releases, held or all movement, and the wheel as buttons four and five per row of travel, posted to `/plugin/terminals/mouse` and encoded by libghostty's mouse encoder with the program's modes and format); `select` in semi-char mode, where the browser's own selection shows the drag and its result (or the click) goes to `/plugin/terminals/select`: a drag, a double or triple click, or a click in a view already selected enters copy mode with that region or point (ghostel's mouse-drag input mode); a focus click only selects the view. Links take clicks in either mode. Otherwise the wheel scrolls the view.
   - **Clipboard.** `C-y`, `M-y` and the browser's paste go through the paste encoder, bracketed when the program asks; `terminal-paste-protection` (off) asks before an unbracketed paste `paste-safe?` rejects. OSC 52 writes (`terminal-enable-osc52`, off) go to the kill ring and, through the tab that last typed into the terminal, to the browser clipboard; the mirror denies them when off; reads are never answered.
   - **Links.** OSC 8 runs carry their URI; URLs and FILE:LINE[:COLUMN] references to files that exist are found per line of the program's (wrapped rows joined, 50 at most, the cursor's line skipped) as rows are copied (`terminal-enable-url-detection`, `terminal-enable-file-detection`). Web links are `<a target=_blank>`; others go to `/plugin/terminals/link` and open in their file's buffer in another view at the line; `C-c C-n`/`C-c C-p` move between links in copy mode; `RET` there opens one (a web one through a `terminalOpen` page instruction).
   - **Colours.** The page script resolves `--terminal-foreground`, `--terminal-background`, `--terminal-cursor-background` and the 256 `--terminal-color-N` through a canvas and posts them (`/plugin/terminals/colors`) at start and when stylesheets or the system scheme change; `terminal-colors` overrides. The helper sets them as its terminal's defaults, so it answers OSC 4/10/11/12, and classifies the background as dark or light for `CSI ? 996 n`, reporting a change to programs in mode 2031.
   - **Status line and close-tab question.** A status-line part shows `terminal-status-line-format` (`"(%.30t)"`) and `:Copy`, `:Line` or `:Char`. In a plain tab (not `display-mode: standalone`), `beforeunload` asks while the selected view shows a terminal whose program runs (`terminal-confirm-close-tab`).
   - **Tests.** `unit/copy-text-test.ss`, `unit/links-test.ss`, more of `unit/screen-test.ss` (grid cells, OSC 8 runs) and `unit/protocol-test.ss`, a colour-query case in `integration/helper-test.ss`, and `integration/modes-test.ss` (copy mode, fast exit, `C-SPC`, line mode across a full reset, OSC 52 off and on, the status line, the mouse to a program, a drag to copy mode, links). Shared kernel helpers moved to `tests/support/terminals.ss`; `tests/support/recording-page.ss` stands in for the page; helpers a killed test run left are stopped by pid when the next starts.
   - **Divergences from ghostel** (also in `docs/emacs-equivalents.md`):
     - Copy mode is a copy (see above), drawn with palette foreground colours and links only: no bold, backgrounds, inverse or exact colours, and fallback-font glyphs are not held to the grid there. No hint cursor (`ghostel-readonly-fake-cursor`).
     - `RET` in copy mode copies the region and leaves (the brief), where ghostel's fast-exit `RET` sends a return to the program; both open a link at point.
     - No Emacs mode (live read-only) and so no `ghostel-readonly-default-mode`; the trigger settings take `'default`, `'copy` or `#f`. Tuna has no isearch yet, so neither "isearch enters copy mode" nor `ghostel-point-leave-input-mode` is built.
     - A drag over the rows shows the browser's selection until release; Emacs draws its region as it goes. No middle-click primary paste (browsers have none). ghostel has no click-to-move-the-cursor at a prompt, so neither has Tuna. Alternate scroll (mode 1007) is not honoured, as in ghostel.
     - `terminal-paste-protection` is new (ghostel never asks); OSC 52's browser copy is best effort: Chrome writes for the focused tab, Firefox only soon after a key, Safari is expected to refuse, and the echo area then says the text is on the kill ring only.
     - Web links open in a new browser tab (Tuna has no `browse-url`); detection runs as rows are copied, not on `ghostel-plain-link-detection-delay`'s timer.
     - Line mode shows its input over the cursor's row rather than editing the buffer there; it adopts no text already typed at the prompt (that needs OSC 133 input marks, stage 4), completes nothing on `TAB`, and has no `ghostel-line-mode-send-functions`.
     - The title shows in a status-line part after the buffer's name, not by replacing it (`ghostel-buffer-identification-format`'s `%b`).
     - Colours come from the browser's tokens, not Emacs faces; the close-tab question is Tuna's own (ghostel's nearest is `kill-emacs-query-functions`).
   - **Open:** the real `beforeunload` dialog could not be seen in the automated Chrome (it accepts dialogs; the handler's request was checked); the agent's synthetic wheel reached vim only as a DOM `WheelEvent`; copy mode's colours; a gesture-driven OSC 52 fallback ("press a key to copy") for browsers that refuse.
4. **Programs talking to Tuna.** Hooks for OSC 133 prompts (prompt navigation, command start and finish), notifications (OSC 9/777), progress, program status (OSC 7501) and unknown sequences; shell integration scripts for bash, zsh and fish, injected as ghostel does; a small program-status display.
5. **Reboots and heavy output.** Saved screens and revive after a reboot; dirty-row copying and paced redraw for floods; many terminals with big scrollback (compression).
